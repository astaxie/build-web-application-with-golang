# 2.7 Eşzamanlılık

Go'nun 21. yüzyılın C'si olduğu söylenir. Bence bunun iki nedeni var. Birincisi, Go basit bir dil. İkincisi, eşzamanlılık günümüz dünyasının en gözde konularından biri ve Go bu özelliği dil seviyesinde destekliyor.

## goroutine

goroutine'ler ve eşzamanlılık, Go'nun çekirdek tasarımının bir parçasıdır. İş parçacıklarına (thread) benzerler ama farklı çalışırlar. Go, goroutine'lerinizde belleği paylaşmanız için de tam destek verir. Bir goroutine genellikle 4~5 KB'lık yığın belleği kullanır. Bu yüzden tek bir bilgisayarda binlerce goroutine çalıştırmak zor değildir. Bir goroutine, sistem thread'lerine göre daha hafif, daha verimli ve daha kullanışlıdır.

goroutine'ler Go'da çalışma zamanındaki thread yöneticisi üzerinde çalışır. Yeni bir goroutine oluşturmak için `go` anahtar kelimesini kullanırız; alt seviyede bu aslında bir fonksiyondur ( ***main() bir goroutine'dir*** ).
```Go
go hello(a, b, c)
```
Bir örneğe bakalım.
```Go
package main

import (
	"fmt"
	"runtime"
)

func say(s string) {
	for i := 0; i < 5; i++ {
		runtime.Gosched()
		fmt.Println(s)
	}
}

func main() {
	go say("dünya") // yeni bir goroutine oluştur
	say("merhaba")  // mevcut goroutine
}

```
Çıktı:
```
	merhaba
	dünya
	merhaba
	dünya
	merhaba
	dünya
	merhaba
	dünya
	merhaba
```
Gördüğünüz gibi `go` anahtar kelimesini kullanarak Go'da eşzamanlılıktan yararlanmak çok kolay. Yukarıdaki örnekte bu iki goroutine bir miktar belleği paylaşıyor, ancak şu tasarım ilkesine uymamız çok daha iyi olur: İletişim kurmak için paylaşılan veriyi kullanmayın, veriyi paylaşmak için iletişimi kullanın.

runtime.Gosched(), CPU'nun diğer goroutine'leri çalıştırmasına izin ver ve bir noktada geri dön anlamına gelir.

Go 1.5 ile birlikte çalışma zamanı, GOMAXPROCS ile tanımlanan ve aynı anda çalışacak öntanımlı thread sayısını, CPU'da bulunan çekirdek sayısına ayarlıyor.

Go 1.5'ten önce zamanlayıcı, bütün goroutine'leri çalıştırmak için yalnızca tek bir thread kullanıyordu; yani sadece eşzamanlılık sağlıyordu. Paralel işlemenin avantajından yararlanmak için daha fazla CPU çekirdeği kullanmak istiyorsanız, kullanmak istediğiniz çekirdek sayısını belirlemek üzere runtime.GOMAXPROCS(n) fonksiyonunu çağırmanız gerekir. `n<1` ise hiçbir şey değişmez.

## channel'lar

goroutine'ler aynı bellek adres alanında çalışır; bu yüzden paylaşılan belleğe erişmek istediğinizde senkronizasyonu korumanız gerekir. Peki farklı goroutine'ler arasında nasıl iletişim kurarsınız? Go, `channel` adında çok iyi bir iletişim mekanizması kullanır. Bir `channel`, Unix kabuklarındaki iki yönlü boru hattı gibidir: veri göndermek ya da almak için `channel` kullanırsınız. channel'larda kullanılabilecek tek veri türü `channel` türüdür; bunun için de `chan` anahtar kelimesi kullanılır. Yeni bir `channel` oluşturmak için `make` kullanmanız gerektiğini unutmayın.
```Go
ci := make(chan int)
cs := make(chan string)
cf := make(chan interface{})
```
channel, veri göndermek ya da almak için `<-` operatörünü kullanır.
```Go
ch <- v    // v'yi ch channel'ına gönder.
v := <-ch  // ch'den veri al ve v'ye ata
```
Birkaç örneğe daha bakalım.
```Go
package main

import "fmt"

func sum(a []int, c chan int) {
	total := 0
	for _, v := range a {
		total += v
	}
	c <- total // total değerini c'ye gönder
}

func main() {
	a := []int{7, 2, 8, -9, 4, 0}

	c := make(chan int)
	go sum(a[:len(a)/2], c)
	go sum(a[len(a)/2:], c)
	x, y := <-c, <-c // c'den al

	fmt.Println(x, y, x+y)
}

```
channel'larda veri gönderme ve alma işlemleri öntanımlı olarak bloklar; bu da senkron goroutine'ler kullanmayı çok kolaylaştırır. Bloklamaktan kastım şu: bir goroutine, boş bir channel'dan veri alırken (yani `value := <-ch`), diğer goroutine'ler bu channel'a veri gönderene kadar devam etmez. Diğer taraftan goroutine, bir channel'a gönderdiği veri (yani `ch<-5`) alınana kadar da devam etmez.

## Tamponlu channel'lar

Yukarıda tamponsuz channel'ları tanıttım. Go'da ayrıca tek bir elemandan fazlasını saklayabilen tamponlu channel'lar da var. Örneğin `ch := make(chan bool, 4)` ile burada 4 tane boolean eleman saklayabilen bir channel oluşturuyoruz. Yani bu channel'a bloklanmadan 4 eleman gönderebiliriz; ancak beşinci elemanı göndermeye çalıştığınızda onu alacak bir goroutine yoksa goroutine bloklanacaktır.
```Go
ch := make(chan type, n)

n == 0 ! tamponsuz（bloklar）
n > 0 ! tamponlu（channel'da n eleman olana kadar bloklamaz）
```
Aşağıdaki kodu bilgisayarınızda deneyip bazı değerleri değiştirebilirsiniz.
```Go
package main

import "fmt"

func main() {
	c := make(chan int, 2) // 2'yi 1 yaparsanız çalışma zamanı hatası alırsınız, ama 3 sorun çıkarmaz
	c <- 1
	c <- 2
	fmt.Println(<-c)
	fmt.Println(<-c)
}

```
## Range ve Close

slice ve map'te olduğu gibi tamponlu channel'lar üzerinde de range kullanabiliriz.
```Go
package main

import (
	"fmt"
)

func fibonacci(n int, c chan int) {
	x, y := 1, 1
	for i := 0; i < n; i++ {
		c <- x
		x, y = y, x+y
	}
	close(c)
}

func main() {
	c := make(chan int, 10)
	go fibonacci(cap(c), c)
	for i := range c {
		fmt.Println(i)
	}
}

```
`for i := range c` ifadesi, channel kapatılana kadar channel'dan veri okumayı bırakmaz. Yukarıdaki örnekte channel'ı kapatmak için `close` anahtar kelimesini kullandık. Kapatılmış bir channel üzerinde veri göndermek ya da almak mümkün değildir; bir channel'ın kapalı olup olmadığını sınamak için `v, ok := <-ch` kullanabilirsiniz. `ok` false dönerse, o channel'da hiç veri olmadığı ve channel'ın kapatıldığı anlamına gelir.

channel'ları her zaman üreticilerde kapatmayı, tüketicilerde kapatmamayı unutmayın; aksi halde kolayca panic haline düşersiniz.

Aklınızda tutmanız gereken bir diğer şey de channel'ların dosyalar gibi olmadığıdır. channel'ın tamamen işe yaramaz olduğundan emin olmadıkça ya da range döngülerinden çıkmak istemedikçe onları sık sık kapatmanız gerekmez.

## Select

Yukarıdaki örneklerde yalnızca tek bir channel kullandık, peki birden fazla channel ile nasıl başa çıkabiliriz? Go'da birçok channel'ı dinlemek için `select` adında bir anahtar kelime var.

`select` öntanımlı olarak bloklar ve yalnızca channel'lardan birinde gönderilecek ya da alınacak veri olduğunda çalışmaya devam eder. Aynı anda birden fazla channel kullanıma hazırsa, select hangisini çalıştıracağını rastgele seçer.
```Go
package main

import "fmt"

func fibonacci(c, quit chan int) {
	x, y := 1, 1
	for {
		select {
		case c <- x:
			x, y = y, x+y
		case <-quit:
			fmt.Println("çıkılıyor")
			return
		}
	}
}

func main() {
	c := make(chan int)
	quit := make(chan int)
	go func() {
		for i := 0; i < 10; i++ {
			fmt.Println(<-c)
		}
		quit <- 0
	}()
	fibonacci(c, quit)
}

```
`select`, tıpkı `switch` gibi bir `default` durumuna da sahiptir. channel'ların hiçbiri kullanıma hazır değilken default durumunu çalıştırır (artık channel'ı beklemez).
```Go
select {
case i := <-c:
// i'yi kullan
default:
// c bloklandığında burası çalışır
}
```
## Zaman aşımı

Bazen bir goroutine bloklanır. Tüm programın bloklanmasını engellemek için bundan nasıl kaçınabiliriz? Çok basit, select içinde bir zaman aşımı belirleyebiliriz.
```Go
func main() {
	c := make(chan int)
	o := make(chan bool)
	go func() {
		for {
			select {
			case v := <-c:
				println(v)
			case <-time.After(5 * time.Second):
				println("zaman aşımı")
				o <- true
				break
			}
		}
	}()
	<-o
}

```
## Runtime goroutine

`runtime` paketi, goroutine'lerle uğraşmak için bazı fonksiyonlar barındırır.

- `runtime.Goexit()`

	Mevcut goroutine'den çıkar, ancak defer edilmiş fonksiyonlar her zamanki gibi çalıştırılır.

- `runtime.Gosched()`

	Zamanlayıcının diğer goroutine'leri çalıştırmasına izin verir ve bir noktada geri döner.

- `runtime.NumCPU() int`

	CPU çekirdeklerinin sayısını döndürür

- `runtime.NumGoroutine() int`

	goroutine sayısını döndürür

- `runtime.GOMAXPROCS(n int) int`

	Kaç CPU çekirdeği kullanmak istediğinizi ayarlar

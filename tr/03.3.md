# 3.3 Go, Web'le nasıl çalışıyor

Önceki bölümde basit bir web sunucusu oluşturmak için `net/http` paketini kullanmayı öğrendik. Oradaki çalışma prensiplerinin tamamı, bu bölümün ilk kısmında konuşacaklarımızla aynıdır.

## Web prensiplerindeki kavramlar

Request: Kullanıcılardan gelen istek verisi; POST, GET, Cookie ve URL bilgilerini içerir.

Response: Sunucudan istemcilere gönderilen yanıt verisi.

Conn: İstemcilerle sunucular arasındaki bağlantılar.

Handler: İsteği işleme mantığı ve yanıtın üretilmesi.

1. Dinleme yapan bir soket oluştur, bir portu dinle ve istemcileri bekle.
2. İstemcilerden gelen istekleri kabul et.
3. İstekleri işle, HTTP başlığını oku. İstek POST methodunu kullanıyorsa, mesaj gövdesindeki veriyi oku ve handler'lara geçir. Son olarak soket, yanıt verisini istemcilere döndürür.

Aşağıdaki üç sorunun yanıtını bildiğimizde, Go'da web'in nasıl çalıştığını anlamak kolaylaşır.

- Bir portu nasıl dinleriz?
- İstemci isteklerini nasıl kabul ederiz?
- Handler'ları nasıl atarız?

Önceki bölümde Go'nun bu adımları `ListenAndServe` ile hallettiğini görmüştük: bir sunucu nesnesi ilklendirilir, ardından `net.Listen("tcp", addr)` çağrılarak bir TCP dinleyicisi kurulur ve belirli bir adres ile port dinlenir.

`http` paketinin kaynak koduna bir göz atalım.

```go
//Derleme sürümü go1.1.2.
func (srv *Server) Serve(l net.Listener) error {
	defer l.Close()
	var tempDelay time.Duration // accept başarısız olduğunda ne kadar bekleneceği
	for {
		rw, e := l.Accept()
		if e != nil {
			if ne, ok := e.(net.Error); ok && ne.Temporary() {
				if tempDelay == 0 {
					tempDelay = 5 * time.Millisecond
				} else {
					tempDelay *= 2
				}
				if max := 1 * time.Second; tempDelay > max {
					tempDelay = max
				}
				log.Printf("http: Accept hatası: %v; %v içinde yeniden denenecek", e, tempDelay)
				time.Sleep(tempDelay)
				continue
			}
			return e
		}
		tempDelay = 0
		c, err := srv.newConn(rw)
		if err != nil {
			continue
		}
		go c.serve()
	}
}
```

	
Bir portu dinlemeye başladıktan sonra istemci isteklerini nasıl kabul ediyoruz? Kaynak kodunda, istemci isteklerini işlemek için `srv.Serve(net.Listener)` fonksiyonunun çağrıldığını görebiliriz. Fonksiyonun gövdesinde bir `for{}` döngüsü var. Bu döngü bir isteği kabul eder, yeni bir bağlantı oluşturur, sonra yeni bir goroutine başlatır ve istek verisini `go c.serve()` goroutine'ine geçirir. Go'nun yüksek eşzamanlılığı desteklemesinin yolu işte budur; üstelik her goroutine bağımsızdır.

İstekleri işlemek için belirli fonksiyonları nasıl kullanıyoruz? `conn` önce `c.ReadRequest()` ile isteği ayrıştırır, ardından ilgili handler'ı alır: `handler := sh.srv.Handler`. Bu handler, `ListenAndServe`'ü çağırırken geçtiğimiz ikinci argümandır. `nil` geçtiğimiz için Go kendi öntanımlı handler'ını kullanır: `handler = DefaultServeMux`. Peki `DefaultServeMux` burada ne yapıyor? Aslında o, belirli URL'ler için handler fonksiyonlarını çağırabilen yönlendirici değişkenidir. Bunu biz mi ayarladık? Evet, ayarladık. Bunu ilk satırda `http.HandleFunc("/", sayhelloName)` kullandığımız yerde yaptık. Bu fonksiyonla "/" yolu için yönlendirici kuralını kaydediyoruz. URL `/` olduğunda, yönlendirici `sayhelloName` fonksiyonunu çağırır. DefaultServeMux, farklı yollar için handler fonksiyonlarını almak üzere ServerHTTP'yi çağırır; bu örnekte çağrılan `sayhelloName` olur. Son olarak sunucu veriyi yazar ve istemcilere yanıt verir.

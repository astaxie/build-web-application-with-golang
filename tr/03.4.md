# 3.4 Http paketine giriş

Önceki bölümlerde web'in çalışma akışını öğrendik ve Go'nun `http` paketinden biraz söz ettik. Bu bölümde `http` paketindeki iki çekirdek fonksiyonu öğreneceğiz: Conn ve ServeMux.

## Conn içindeki goroutine

Sıradan HTTP sunucularının aksine Go, yüksek eşzamanlılık ve performans elde etmek için Conn tarafından başlatılan her iş için bir goroutine kullanır; böylece her iş bağımsızdır.

Go, istemcilerden gelen yeni bağlantıları beklemek için aşağıdaki kodu kullanır.
```Go
c, err := srv.newConn(rw)
if err != nil {
	continue
}
go c.serve()
```	
Gördüğünüz gibi her bağlantı için yeni bir goroutine oluşturuluyor ve istekten veri okuyabilen handler bu goroutine'e geçiriliyor.

## Özelleştirilmiş ServeMux

Önceki bölümlerde conn.server'ı incelerken Go'nun öntanımlı yönlendiricisini kullandık; bu yönlendirici istek verisini arka taraftaki bir handler'a geçiriyordu.

Öntanımlı yönlendiricinin struct'ı:
```Go
type ServeMux struct {
	mu sync.RWMutex        // eşzamanlılık nedeniyle burada bir mutex kullanmak zorundayız
	m  map[string]muxEntry // yönlendirme kuralları, her string bir handler'a eşlenir
}
```	
muxEntry struct'ı:
```Go
type muxEntry struct {
	explicit bool // tam eşleşme olup olmadığı
	h        Handler
}
```	
Handler interface'i:
```Go
type Handler interface {
	ServeHTTP(ResponseWriter, *Request)  // yönlendirmeyi gerçekleştiren
}
```	
`Handler` bir interface'tir; peki `sayhelloName` fonksiyonu bu interface'i uygulamadıysa onu nasıl handler olarak ekleyebildik? Yanıt, `http` paketindeki `HandlerFunc` adlı başka bir türde saklı. `sayhelloName` methodumuzu tanımlamak için `HandlerFunc`'ı çağırdık, böylece `sayhelloName` aynı anda `Handler`'ı da uygulamış oldu. Bu, `HandlerFunc(f)` çağırmak gibidir; `f` fonksiyonu zorla `HandlerFunc` türüne dönüştürülür.
```Go
type HandlerFunc func(ResponseWriter, *Request)

// ServeHTTP, f(w, r) çağrısını yapar.
func (f HandlerFunc) ServeHTTP(w ResponseWriter, r *Request) {
	f(w, r)
}
```	
Peki yönlendirme kurallarını belirledikten sonra yönlendirici handler'ları nasıl çağırıyor?

Yönlendirici, istekleri aldığında `mux.handler.ServeHTTP(w, r)` çağrısını yapar. Yani bu interface'i uygulamış olan handler'ların `ServeHTTP` interface'ini çağırır.

Şimdi `mux.handler`'ın nasıl çalıştığına bakalım.
```Go
func (mux *ServeMux) handler(r *Request) Handler {
	mux.mu.RLock()
	defer mux.mu.RUnlock()

	// Host'a özgü desen, genel olanlardan önceliklidir
	h := mux.match(r.Host + r.URL.Path)
	if h == nil {
		h = mux.match(r.URL.Path)
	}
	if h == nil {
		h = NotFoundHandler()
	}
	return h
}
```	
Yönlendirici, map içinde saklanan ilgili handler'ı bulmak için isteğin URL'sini anahtar olarak kullanır, ardından veriyi işleyecek fonksiyonları çalıştırmak için handler.ServeHTTP'yi çağırır.

Artık öntanımlı yönlendiricinin çalışma akışını anlamış olmalısınız. Go aslında özelleştirilmiş yönlendiricileri de destekler. `ListenAndServe`'in ikinci argümanı özelleştirilmiş yönlendiricileri yapılandırmak içindir. Bu argüman bir `Handler` interface'idir. Dolayısıyla `Handler` interface'ini uygulayan her yönlendirici kullanılabilir.

Aşağıdaki örnek, basit bir yönlendiricinin nasıl uygulanacağını gösteriyor.
```Go
package main

import (
	"fmt"
	"net/http"
)

type MyMux struct {
}

func (p *MyMux) ServeHTTP(w http.ResponseWriter, r *http.Request) {
	if r.URL.Path == "/" {
		sayhelloName(w, r)
		return
	}
	http.NotFound(w, r)
	return
}

func sayhelloName(w http.ResponseWriter, r *http.Request) {
	fmt.Fprintf(w, "Merhaba myroute!")
}

func main() {
	mux := &MyMux{}
	http.ListenAndServe(":9090", mux)
}
```

# Yönlendirme

Bir yönlendirici (Router) kullanmak istemiyorsanız, yukarıdaki bölümde yazdıklarımızı yine de elde edebilirsiniz: `ListenAndServe`'in ikinci argümanını nil ile değiştirin ve URL'leri bir `HandleFunc` fonksiyonu kullanarak kaydedin. Bu fonksiyon en iyi eşleşmeyi bulmak için kayıtlı tüm URL'leri gezer, bu yüzden kayıt sırasına dikkat etmek gerekir.

örnek kod:
```Go
http.HandleFunc("/", views.ShowAllTasksFunc)
http.HandleFunc("/complete/", views.CompleteTaskFunc)
http.HandleFunc("/delete/", views.DeleteTaskFunc)
    
//ShowAllTasksFunc, öntanımlı olan "/" URL'sini işlemek için kullanılır
//TODO http404 hatası eklenecek
func ShowAllTasksFunc(w http.ResponseWriter, r *http.Request) {
	if r.Method == "GET" {
		context := db.GetTasks("pending") //silinmemiş görevleri istediğinizde true
		//db, veritabanıyla etkileşime giren bir pakettir
		if message != "" {
			context.Message = message
		}
		homeTemplate.Execute(w, context)
		message = ""
	} else {
		message = "Method'a izin verilmiyor"
		http.Redirect(w, r, "/", http.StatusFound)
	}
}
```
Parametreli yönlendirme gerektirmeyen basit uygulamalar için bu yeterlidir, peki buna ihtiyaç duyduğunuzda ne olacak? Ya mevcut araç setlerini ya da framework'leri kullanabilirsiniz; fakat bu kitap golang ile web uygulaması yazmayı anlattığı için bu senaryoyu nasıl ele alacağınızı da öğreteceğiz.

Eşleşme `HandleFunc` fonksiyonunda yapıldığında URL eşleştirilir. Diyelim ki bir yapılacaklar listesi yöneticisi yazıyoruz ve bir görevi silmek istiyoruz; bu uygulama için belirlediğimiz URL `/delete/1` olsun. Silme URL'sini şöyle kaydederiz
    `http.HandleFunc("/delete/", views.DeleteTaskFunc)`
    `/delete/1` bu URL, diğer bütün URL'lere kıyasla en çok "/delete/" URL'siyle eşleşir; böylece `r.URL.path` içinde isteğin URL'sinin tamamını elde ederiz.
```Go
http.HandleFunc("/delete/", views.DeleteTaskFunc)
//DeleteTaskFunc bir görevi silmek için kullanılır, trash = geri dönüşüm kutusuna taşı, delete = kalıcı silme
func DeleteTaskFunc(w http.ResponseWriter, r *http.Request) {
	if r.Method == "DELETE" {
		id := r.URL.Path[len("/delete/"):]
		if id == "all" {
			db.DeleteAll()
			http.Redirect(w, r, "/", http.StatusFound)
		} else {
			id, err := strconv.Atoi(id)
			if err != nil {
				fmt.Println(err)
			} else {
				err = db.DeleteTask(id)
				if err != nil {
					message = "Görev silinirken hata oluştu"
				} else {
					message = "Görev silindi"
				}
				http.Redirect(w, r, "/", http.StatusFound)
			}
		}
	} else {
		message = "Method'a izin verilmiyor"
		http.Redirect(w, r, "/", http.StatusFound)
	}
}
```   
   bağlantı: https://github.com/thewhitetulip/Tasks/blob/master/views/views.go#L170-#L195
   
   Yukarıdaki bu yöntemde temelde şunu yapıyoruz: `/delete/` URL'sini işleyen fonksiyonda isteğin tam URL'sini, yani `/delete/1`'i alıyoruz, ardından string'in bir slice'ını alıp delete kelimesinden sonra başlayan her şeyi, yani asıl parametreyi çıkarıyoruz; bu örnekte bu değer `1`. Sonra `strconv` paketini kullanarak bunu bir tam sayıya çeviriyor ve o taskID'ye sahip görevi siliyoruz.
   
Daha karmaşık senaryolarda da bu yöntemi kullanabiliriz; avantajı, herhangi bir üçüncü parti araç setine ihtiyaç duymamamızdır. Ancak yine de üçüncü parti araç setleri kendi başlarına faydalıdır; hangi yöntemi tercih edeceğinize karar vermelisiniz. Tek bir doğru cevap yok.


## Go kodunun çalışma akışı

Çalışma akışının tamamına bir göz atalım.

- `http.HandleFunc` çağrılır
	1. DefaultServeMux'un HandleFunc'ı çağrılır
	2. DefaultServeMux'un Handle'ı çağrılır
	3. Yönlendirme kuralları DefaultServeMux'un map[string]muxEntry'sine eklenir
- `http.ListenAndServe(":9090", nil)` çağrılır
	1. Server somutlaştırılır
	2. Server'ın ListenAndServe methodu çağrılır
	3. Portu dinlemek için net.Listen("tcp", addr) çağrılır
	4. Bir döngü başlatılır ve döngü gövdesinde istekler kabul edilir
	5. Her istek için bir Conn somutlaştırılır ve bir goroutine başlatılır: `go c.serve()`
	6. İstek verisi okunur: `w, err := c.readRequest()`
	7. handler'ın boş olup olmadığı denetlenir, boşsa DefaultServeMux kullanılır
	8. handler'ın ServeHTTP'si çağrılır
	9. Bu durumda DefaultServeMux içindeki kod çalıştırılır
	10. URL'ye göre handler seçilir ve o handler fonksiyonundaki kod çalıştırılır: `mux.handler.ServeHTTP(w, r)`
	11. handler nasıl seçilir:
		A. Bu URL için yönlendirme kuralları denetlenir
		B. Varsa o handler'daki ServeHTTP çağrılır
		C. Aksi hâlde NotFoundHandler'ın ServeHTTP'si çağrılır

# 5.3 SQLite

SQLite, açık kaynaklı ve gömülü bir ilişkisel veritabanıdır. Kendi kendine yeten, sıfır yapılandırma gerektiren ve transaction destekleyen bir veritabanı motoruna sahiptir. Son derece taşınabilir, kullanımı kolay, küçük, verimli ve güvenilir olması öne çıkan özellikleridir. Çoğu durumda bir veritabanı oluşturmak, ona bağlanmak ve üzerinde işlem yapmak için yalnızca SQLite'ın binary dosyası yeterlidir. Gömülü bir veritabanı çözümü arıyorsanız SQLite değerlendirmeye değer. SQLite için Access'in açık kaynaklı sürümü diyebilirsiniz.

## SQLite sürücüleri

Go'da SQLite için pek çok veritabanı sürücüsü var, fakat bunların çoğu `database/sql` interface (arayüz) standartlarını desteklemiyor.

- [https://github.com/mattn/go-sqlite3](https://github.com/mattn/go-sqlite3) `database/sql`'i destekliyor, cgo tabanlı.
- [https://github.com/feyeleanor/gosqlite3](https://github.com/feyeleanor/gosqlite3) `database/sql`'i desteklemiyor, cgo tabanlı.
- [https://github.com/phf/go-sqlite3](https://github.com/phf/go-sqlite3) `database/sql`'i desteklemiyor, cgo tabanlı.

SQLite sürücüleri arasında `database/sql` interface standardını destekleyen tek sürücü ilk sıradaki; bu yüzden projelerimde bunu kullanıyorum. Böylece ileride gerekirse kodumu taşımak da kolay olacak.

## Örnekler

Aşağıdaki SQL'i oluşturuyoruz:
```sql
	CREATE TABLE `userinfo` (
	    `uid` INTEGER PRIMARY KEY AUTOINCREMENT,
	    `username` VARCHAR(64) NULL,
	    `department` VARCHAR(64) NULL,
	    `created` DATE NULL
	);
```
Bir örnek:
```Go
	package main
	
	import (
	    "database/sql"
	    "fmt"
	    "time"
	    _ "github.com/mattn/go-sqlite3"
	)
	
	func main() {
	    db, err := sql.Open("sqlite3", "./foo.db")
	    checkErr(err)
	
	    // ekleme
	    stmt, err := db.Prepare("INSERT INTO userinfo(username, department, created) values(?,?,?)")
	    checkErr(err)
	
	    res, err := stmt.Exec("astaxie", "研发部门", "2012-12-09")
	    checkErr(err)
	
	    id, err := res.LastInsertId()
	    checkErr(err)
	
	    fmt.Println(id)
	    // güncelleme
	    stmt, err = db.Prepare("update userinfo set username=? where uid=?")
	    checkErr(err)
	
	    res, err = stmt.Exec("astaxieupdate", id)
	    checkErr(err)
	
	    affect, err := res.RowsAffected()
	    checkErr(err)
	
	    fmt.Println(affect)
	
	    // sorgulama
	    rows, err := db.Query("SELECT * FROM userinfo")
	    checkErr(err)
	    var uid int
	    var username string
	    var department string
	    var created time.Time
	    
	    for rows.Next() {
	        err = rows.Scan(&uid, &username, &department, &created)
	        checkErr(err)
	        fmt.Println(uid)
	        fmt.Println(username)
	        fmt.Println(department)
	        fmt.Println(created)
	    }
	    
	    rows.Close() //kapatmak iyi bir alışkanlıktır
	    
	    // silme
	    stmt, err = db.Prepare("delete from userinfo where uid=?")
	    checkErr(err)
	
	    res, err = stmt.Exec(id)
	    checkErr(err)
	
	    affect, err = res.RowsAffected()
	    checkErr(err)
	
	    fmt.Println(affect)
	
	    db.Close()
	
	}
	
	func checkErr(err error) {
	    if err != nil {
	        panic(err)
	    }
	}
```
Kodun önceki bölümdekiyle neredeyse aynı olduğunu fark etmişsinizdir; yalnızca kaydedilen sürücünün adını değiştirdik ve SQLite'a bağlanmak için `sql.Open`'ı farklı biçimde çağırdık.

Dikkat: bazen birden fazla satırınız olmadığı için `for` ifadesini kullanamazsınız; böyle durumlarda `if` ifadesini kullanabilirsiniz
```Go
    if rows.Next() {
        err = rows.Scan(&uid, &username, &department, &created)
        checkErr(err)
        fmt.Println(uid)
        fmt.Println(username)
        fmt.Println(department)
        fmt.Println(created)
    }
```
Ayrıca mutlaka bir `rows.Next()` çağrısı yapmalısınız; bunu kullanmadan `Scan` fonksiyonuyla veri çekemezsiniz.

Transaction'lar
===============

Yukarıdaki örnek, veritabanından nasıl veri çekeceğinizi gösteriyor. Fakat bir web uygulaması yazmak istediğinizde yalnızca veritabanından veri çekmek değil, veritabanına veri yazmak da gerekecek. Bunun için transaction kullanmalısınız; çünkü veritabanına erişen birden fazla goroutine olması gibi çeşitli nedenlerle veritabanı kilitlenebilir. Bu, web uygulamanızda istenmeyen bir durumdur ve transaction kullanmak, veritabanı işlemlerinizin koşullara göre ya tamamen başarılı olmasını ya da tamamen başarısız olmasını sağlamada etkilidir. Transaction kullanmanın web uygulamasında pek çok şeyin ters gitmesini engelleyebileceği açıktır.
```Go
    trashSQL, err := database.Prepare("update task set is_deleted='Y',last_modified_at=datetime() where id=?")
    if err != nil {
        fmt.Println(err)
    }
    tx, err := database.Begin()
    if err != nil {
    	fmt.Println(err)
    }
    _, err = tx.Stmt(trashSQL).Exec(id)
    if err != nil {
    	fmt.Println("rollback yapılıyor")
    	tx.Rollback()
    } else {
    	tx.Commit()
    }
```    
Yukarıdaki kod bloğundan da anlaşılacağı gibi, önce bir ifade (statement) hazırlıyorsunuz, ardından onu çalıştırıyorsunuz; bu çalıştırmanın sonucuna göre de işlemi ya geri alıyorsunuz (rollback) ya da kalıcı hâle getiriyorsunuz (commit).

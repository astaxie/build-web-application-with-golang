# 6.2 Oturumlar Go'da nasıl kullanılıyor

6.1 bölümünde oturumların, kullanıcıları doğrulamanın çözümlerinden biri olduğunu ve şimdilik Go standart kütüphanesinin oturumlar ya da oturum yönetimi için yerleşik bir desteği bulunmadığını öğrendik. Bu yüzden Go'da kendi oturum yöneticimizi yazacağız.

## Oturum oluşturma

Oturumların ardındaki temel ilke şudur: sunucu her bir istemci için bilgi tutar ve istemciler bu bilgiye erişmek için benzersiz oturum id'lerini kullanır. Kullanıcılar web uygulamasını ziyaret ettiğinde sunucu, gerektikçe aşağıdaki üç adımla yeni bir oturum oluşturur:

- Benzersiz bir oturum id'si oluştur
- Bir veri saklama alanı aç: normalde oturumları bellekte saklarız, fakat sistem beklenmedik biçimde kesintiye uğrarsa bütün oturum verilerini kaybedersiniz. Web uygulaması, örneğin elektronik ticarette olduğu gibi hassas verilerle çalışıyorsa bu çok ciddi bir sorun olabilir. Bu sorunu çözmek için oturum verilerinizi bunun yerine bir veritabanında ya da dosya sisteminde saklayabilirsiniz. Bu yöntem verinin kalıcılığını daha güvenilir kılar ve veriyi diğer uygulamalarla paylaşmayı kolaylaştırır; bedeli ise bu oturumları okuyup yazmak için sunucu tarafında daha fazla IO gerekmesidir.
- Benzersiz oturum id'sini istemciye gönder.

Buradaki kilit adım, benzersiz oturum id'sini istemciye göndermektir. Standart bir HTTP yanıtı bağlamında bunu yapmak için yanıt satırını, başlığı ya da gövdeyi kullanabilirsiniz; dolayısıyla oturum id'lerini istemcilere göndermenin iki yolu var: çerezler ya da URL yeniden yazımı.

- Çerezler: sunucu, bir oturum id'sini istemciye göndermek için yanıt başlığı içinde kolayca `Set-cookie` kullanabilir; istemci de sonraki isteklerinde bu çerezi kullanır. Oturum bilgisi içeren çerezlerin son kullanma süresini genellikle 0 olarak belirleriz; bu, çerezin bellekte saklanacağı ve yalnızca kullanıcılar tarayıcılarını kapattıktan sonra silineceği anlamına gelir.
- URL yeniden yazımı: oturum id'sini bütün sayfaların URL'sine argüman olarak ekle. Bu yol dağınık görünüyor, fakat istemciler tarayıcılarında çerezleri devre dışı bıraktıysa en iyi seçenektir.

## Oturumları yönetmek için Go kullanmak

Oturumların nasıl kurulduğundan söz ettik, artık konuya dair genel bir fikriniz olmalı; peki oturumları dinamik sayfalarda nasıl kullanabiliriz? Go oturum yöneticimizi yazmayı sürdürebilmek için bir oturumun yaşam döngüsüne daha yakından bakalım.

### Oturum yönetimi tasarımı

Oturum yönetimi tasarımındaki bazı kilit noktaların listesi aşağıda.

- Global oturum yöneticisi.
- Oturum id'sini benzersiz tut.
- Her kullanıcı için bir oturum bulunsun.
- Oturumların bellekte, dosyada ya da veritabanında saklanması.
- Süresi dolmuş oturumların ele alınması.

Şimdi eksiksiz bir Go oturum yöneticisi örneğini ve bazı tasarım kararlarının ardındaki gerekçeleri inceleyeceğiz.

### Oturum yöneticisi

Global bir oturum yöneticisi tanımlayalım:
```Go
	type Manager struct {
	    cookieName  string     //gizli çerez adı
	    lock        sync.Mutex // session'ı korur
	    provider    Provider
	    maxlifetime int64
	}
	
	func NewManager(provideName, cookieName string, maxlifetime int64) (*Manager, error) {
	    provider, ok := provides[provideName]
	    if !ok {
	        return nil, fmt.Errorf("session: bilinmeyen sağlayıcı %q (import unutuldu mu?)", provideName)
	    }
	    return &Manager{provider: provider, cookieName: cookieName, maxlifetime: maxlifetime}, nil
	}
```
`main()` fonksiyonu içinde global bir oturum yöneticisi oluşturalım:
```Go
	var globalSessions *session.Manager
	// Sonra oturum yöneticisini ilklendirelim
	func init() {
	    globalSessions = NewManager("memory","gosessionid",3600)
	}
```
Oturumları bellekte, dosya sisteminde ya da doğrudan veritabanında olmak üzere birçok şekilde saklayabileceğimizi biliyoruz. Oturum yöneticimizin altta yatan yapısını temsil etmek için bir `Provider` interface'i (arayüz) tanımlamamız gerekiyor:
```Go
	type Provider interface {
	    SessionInit(sid string) (Session, error)
	    SessionRead(sid string) (Session, error)
	    SessionDestroy(sid string) error
	    SessionGC(maxLifeTime int64)
	}
```
- `SessionInit` bir oturumun ilklendirilmesini gerçekleştirir ve başarılı olursa yeni bir oturum döndürür.
- `SessionRead` ilgili sid ile temsil edilen oturumu döndürür. Oturum halihazırda yoksa yeni bir tane oluşturup döndürür.
- `SessionDestroy` verilen bir sid'ye karşılık gelen oturumu siler.
- `SessionGC` süresi dolmuş oturum değişkenlerini `maxLifeTime` değerine göre siler.

Peki oturum interface'imizde hangi methodlar bulunmalı? Web geliştirme konusunda biraz deneyiminiz varsa oturumlar için yalnızca dört işlem olduğunu biliyorsunuzdur: değer atama, değer alma, değer silme ve güncel oturum id'sini alma. Dolayısıyla oturum interface'imizde bu işlemleri yapacak dört method olmalı.
```Go
	type Session interface {
	    Set(key, value interface{}) error //session değerini ata
	    Get(key interface{}) interface{}  //session değerini al
	    Delete(key interface{}) error     //session değerini sil
	    SessionID() string                //güncel sessionID'yi döndür
	}
```
Bu tasarımın kökleri `database/sql/driver`'a dayanıyor; orada önce interface tanımlanır, sonra kullanmak istediğimizde belirli yapılar kaydedilir. Aşağıdaki kod, bir oturum kayıt fonksiyonunun iç uygulamasıdır.
```Go
	var provides = make(map[string]Provider)

	// Register, verilen isimle bir session sağlayıcısını kullanılabilir hale getirir.
	// Aynı isimle Register iki kez çağrılırsa ya da driver nil ise
	// panic verir.
	func Register(name string, provider Provider) {
	    if provider == nil {
	        panic("session: Register sağlayıcısı nil")
	    }
	    if _, dup := provides[name]; dup {
	        panic("session: Register şu sağlayıcı için iki kez çağrıldı: " + name)
	    }
	    provides[name] = provider
	}
```
### Benzersiz oturum id'leri

Oturum id'leri web uygulamalarının kullanıcılarını birbirinden ayırt etmek içindir, bu yüzden benzersiz olmaları gerekir. Aşağıdaki kod bu amaca nasıl ulaşılacağını gösteriyor:
```Go
	func (manager *Manager) sessionId() string {
	    b := make([]byte, 32)
	    if _, err := io.ReadFull(rand.Reader, b); err != nil {
	        return ""
	    }
	    return base64.URLEncoding.EncodeToString(b)
	}
```
### Oturum oluşturmak

Kullanıcı işlemlerini doğrulamak için ya yeni bir oturum ayırmamız ya da var olan bir oturumu almamız gerekir. `SessionStart` fonksiyonu, güncel kullanıcıyla ilgili herhangi bir oturumun var olup olmadığını denetler ve hiçbiri bulunamazsa yeni bir oturum oluşturur.
```Go
	func (manager *Manager) SessionStart(w http.ResponseWriter, r *http.Request) (session Session) {
	    manager.lock.Lock()
	    defer manager.lock.Unlock()
	    cookie, err := r.Cookie(manager.cookieName)
	    if err != nil || cookie.Value == "" {
	        sid := manager.sessionId()
	        session, _ = manager.provider.SessionInit(sid)
	        cookie := http.Cookie{Name: manager.cookieName, Value: url.QueryEscape(sid), Path: "/", HttpOnly: true, MaxAge: int(manager.maxlifetime)}
	        http.SetCookie(w, &cookie)
	    } else {
	        sid, _ := url.QueryUnescape(cookie.Value)
	        session, _ = manager.provider.SessionRead(sid)
	    }
	    return
	}
```
Aşağıda oturumları bir giriş işlemi için kullanan bir örnek var.
```Go
	func login(w http.ResponseWriter, r *http.Request) {
	    sess := globalSessions.SessionStart(w, r)
	    r.ParseForm()
	    if r.Method == "GET" {
	        t, _ := template.ParseFiles("login.gtpl")
	        w.Header().Set("Content-Type", "text/html")
	        t.Execute(w, sess.Get("username"))
	    } else {
	        sess.Set("username", r.Form["username"])
	        http.Redirect(w, r, "/", 302)
	    }
	}
```
### Değer işlemleri: set, get ve delete

`SessionStart` fonksiyonu, oturum interface'ini uygulayan bir değişken döndürür. Peki bunu nasıl kullanırız?

Yukarıdaki örnekte temel bir işlem olarak `session.Get("uid")` kullanımını gördünüz. Şimdi daha ayrıntılı bir örneği inceleyelim.
```Go
	func count(w http.ResponseWriter, r *http.Request) {
	    sess := globalSessions.SessionStart(w, r)
	    createtime := sess.Get("createtime")
	    if createtime == nil {
	        sess.Set("createtime", time.Now().Unix())
	    } else if (createtime.(int64) + 360) < (time.Now().Unix()) {
	        globalSessions.SessionDestroy(w, r)
	        sess = globalSessions.SessionStart(w, r)
	    }
	    ct := sess.Get("countnum")
	    if ct == nil {
	        sess.Set("countnum", 1)
	    } else {
	        sess.Set("countnum", (ct.(int) + 1))
	    }
	    t, _ := template.ParseFiles("count.gtpl")
	    w.Header().Set("Content-Type", "text/html")
	    t.Execute(w, sess.Get("countnum"))
	}
```
Gördüğünüz gibi oturumlar üzerinde işlem yapmak, Set, Get ve Delete işlemlerinde anahtar/değer kalıbını kullanmaktan ibaret.

Oturumlarda son kullanma süresi kavramı olduğu için GC'yi, oturumun en son değiştirilme zamanını güncelleyecek biçimde tanımlarız. Böylece GC, süresi dolmuş ama hâlâ kullanılmakta olan oturumları silmez.

### Oturumları sıfırlama

Web uygulamalarında bir çıkış işlemi olduğunu biliyoruz. Kullanıcılar çıkış yaptığında ilgili oturumu silmemiz gerekir. Sıfırlama işlemini yukarıdaki örnekte zaten kullandık - şimdi fonksiyonun gövdesine bakalım.
```Go
	// sessionid'yi yok et
	func (manager *Manager) SessionDestroy(w http.ResponseWriter, r *http.Request){
	    cookie, err := r.Cookie(manager.cookieName)
	    if err != nil || cookie.Value == "" {
	        return
	    } else {
	        manager.lock.Lock()
	        defer manager.lock.Unlock()
	        manager.provider.SessionDestroy(cookie.Value)
	        expiration := time.Now()
	        cookie := http.Cookie{Name: manager.cookieName, Path: "/", HttpOnly: true, Expires: expiration, MaxAge: -1}
	        http.SetCookie(w, &cookie)
	    }
	}
```
### Oturumları silme

Oturum yöneticisinin bir oturumu nasıl sileceğine bakalım. GC'yi `main()` fonksiyonunda başlatmamız gerekiyor:
```Go
	func init() {
	    go globalSessions.GC()
	}
	
	func (manager *Manager) GC() {
	    manager.lock.Lock()
	    defer manager.lock.Unlock()
	    manager.provider.SessionGC(manager.maxlifetime)
	    time.AfterFunc(time.Duration(manager.maxlifetime), func() { manager.GC() })
	}
```
GC'nin, `time` paketindeki zamanlayıcı fonksiyonundan tam anlamıyla yararlandığını görüyoruz. Oturumun süresi dolduğunda GC'yi otomatik olarak çağırır ve böylece bütün oturumların `maxLifeTime` boyunca kullanılabilir olmasını sağlar. Benzer bir çözüm çevrimiçi kullanıcıları saymak için de kullanılabilir.

## Özet

Buraya kadar, web uygulamasındaki global oturumları yönetmek için bir oturum yöneticisi yazdık ve `Session`'ın saklama uygulaması olarak `Provider` interface'ini tanımladık. Sonraki bölümde, ileride başvurabileceğiniz ek oturum saklama yapıları için `Provider`'ı nasıl uygulayacağımızı konuşacağız.

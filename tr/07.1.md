# 7.1 XML

XML, web servislerinde yaygın olarak kullanılan bir veri iletişim biçimidir. Günümüzde web geliştirmede giderek daha önemli bir rol üstleniyor. Bu bölümde, Go'nun standart kütüphanesiyle XML'in nasıl kullanılacağını anlatacağız.

XML'in söz dizimini ya da kurallarını öğretmeye çalışmayacağım. Bunun için lütfen XML'in kendisiyle ilgili dokümantasyonu okuyun. Biz yalnızca Go'da XML dosyalarının nasıl kodlanıp çözüleceğine odaklanacağız.

Diyelim ki bilişim alanında çalışıyorsunuz ve aşağıdaki XML yapılandırma dosyasıyla uğraşmanız gerekiyor:
```xml
<?xml version="1.0" encoding="utf-8"?>
<servers version="1">
    <server>
        <serverName>Shanghai_VPN</serverName>
        <serverIP>127.0.0.1</serverIP>
    </server>
    <server>
        <serverName>Beijing_VPN</serverName>
        <serverIP>127.0.0.2</serverIP>
    </server>
</servers>
```
Yukarıdaki XML belgesi, sunucunuz hakkında iki tür bilgi içeriyor: sunucu adı ve IP. Sonraki örneklerimizde bu belgeyi kullanacağız.

## XML ayrıştırma

Bu XML belgesini nasıl ayrıştıracağız? Bunun için Go'nun `xml` paketindeki `Unmarshal` fonksiyonunu kullanabiliriz.

	func Unmarshal(data []byte, v interface{}) error

`data` parametresi bir XML kaynağından gelen veri akışını alır, `v` ise ayrıştırılan XML'i aktarmak istediğiniz yapıdır. Bu bir interface (arayüz) türüdür; yani XML'i istediğiniz herhangi bir yapıya dönüştürebilirsiniz. Burada yalnızca XML'den `struct` türüne nasıl dönüştürüleceğini konuşacağız, çünkü ikisi de benzer ağaç yapılarına sahiptir.

Örnek kod:
```Go
package main

import (
    "encoding/xml"
    "fmt"
    "io/ioutil"
    "os"
)

type Recurlyservers struct {
    XMLName     xml.Name `xml:"servers"`
    Version     string   `xml:"version,attr"`
    Svs         []server `xml:"server"`
    Description string   `xml:",innerxml"`
}

type server struct {
    XMLName    xml.Name `xml:"server"`
    ServerName string   `xml:"serverName"`
    ServerIP   string   `xml:"serverIP"`
}

func main() {
    file, err := os.Open("servers.xml") // Okuma erişimi için.     
    if err != nil {
        fmt.Printf("hata: %v", err)
        return
    }
    defer file.Close()
    data, err := ioutil.ReadAll(file)
    if err != nil {
        fmt.Printf("hata: %v", err)
        return
    }
    v := Recurlyservers{}
    err = xml.Unmarshal(data, &v)
    if err != nil {
        fmt.Printf("hata: %v", err)
        return
    }

    fmt.Println(v)
}
```
XML aslında bir ağaç veri yapısıdır; Go'da struct kullanarak buna çok benzer bir yapı tanımlayabilir, ardından `xml.Unmarshal` ile XML'i struct nesnemize dönüştürebiliriz. Örnek kod aşağıdaki içeriği ekrana basacaktır:
```xml
{{ servers} 1 [{{ server} Shanghai_VPN 127.0.0.1} {{ server} Beijing_VPN 127.0.0.2}]
<server>
    <serverName>Shanghai_VPN</serverName>
    <serverIP>127.0.0.1</serverIP>
</server>
<server>
    <serverName>Beijing_VPN</serverName>
    <serverIP>127.0.0.2</serverIP>
</server>
}
```
XML belgesini karşılık gelen struct nesnesine ayrıştırmak için `xml.Unmarshal` kullanıyoruz. Struct'ımızda `xml:"serverName"` gibi bir şeyler olduğunu görmüş olmalısınız. Bu, reflection (yansıma) işlemine yardımcı olan ve `struct tags` adı verilen bir struct özelliğidir. `Unmarshal`'ın tanımına yeniden bakalım:
```Go
func Unmarshal(data []byte, v interface{}) error
```
İlk argüman bir XML veri akışıdır. İkinci argüman saklama türüdür ve struct, slice ile string türlerini destekler. Go'nun XML paketi veri eşlemesi için reflection kullanır, bu yüzden v içindeki tüm alanların dışarı açık olması gerekir. Ancak bu bir soruna yol açar: hangi XML alanının, eşlenen hangi struct alanına karşılık geldiğini nasıl biliyor? Yanıt şu: XML ayrıştırıcı veriyi belirli bir sırayla ayrıştırır. Kütüphane önce eşleşen struct tag'ini bulmaya çalışır. Bir eşleşme bulunamazsa struct alan adları arasında arama yapar. Tüm tag'lerin, alan adlarının ve XML elemanlarının büyük-küçük harfe duyarlı olduğunu unutmayın; bu yüzden eşlemenin başarılı olması için birebir bir karşılık bulunduğundan emin olmalısınız.

Go'nun reflection mekanizması, bu tag bilgisini kullanarak XML verisini bir struct nesnesine yansıtmanıza olanak tanır. Go'daki reflection hakkında daha fazlasını öğrenmek isterseniz, struct tag'leri ve reflection ile ilgili paket dokümantasyonunu okuyun.

`xml` paketini kullanarak XML belgelerini struct'lara ayrıştırırken geçerli bazı kurallar şunlardır:

- Alanın türü string ya da []byte ise ve `",innerxml"` tag'ine sahipse, `Unmarshal` ona ham XML verisini atar; yukarıdaki örnekteki `Description` gibi: 

	Shanghai_VPN127.0.0.1Beijing_VPN127.0.0.2

- Bir alanın adı `XMLName` ve türü `xml.Name` ise, eleman adını alır; yukarıdaki örnekteki `servers` gibi.
- Bir alanın tag'i karşılık gelen eleman adını içeriyorsa, o da eleman adını alır; yukarıdaki örnekteki `servername` ve `serverip` gibi.
- Bir alanın tag'i `",attr"` içeriyorsa, karşılık gelen elemanın niteliğini alır; yukarıdaki örnekteki `version` gibi.
- Bir alanın tag'i `"a>b>c"` gibi bir şey içeriyorsa, a düğümünün altındaki b düğümünün c elemanının değerini alır.
- Bir alanın tag'i `"="` içeriyorsa, hiçbir şey almaz.
- Bir alanın tag'i `",any"` içeriyorsa, diğer kurallara uymayan tüm alt elemanları alır.
- XML elemanlarında bir ya da daha fazla yorum varsa, bu yorumların tamamı `",comments"` içeren tag'e sahip ilk alana eklenir. Bu alanın türü string ya da []byte olabilir. Böyle bir alan yoksa bütün yorumlar atılır.

Bu kurallar, struct'larda tag'leri nasıl tanımlayacağınızı anlatır. Bu kuralları bir kez anladığınızda, XML'i struct'lara eşlemek yukarıdaki örnek kod kadar kolay olacaktır. Tag'ler ile XML elemanları birebir karşılık geldiği için, aynı seviyedeki birden fazla elemanı temsil etmek üzere slice'lar da kullanabiliriz.

Verinin doğru ayrıştırılabilmesi için struct'lardaki tüm alanların dışarı açık (büyük harfle başlayan) olması gerektiğini unutmayın.

## XML üretme

Peki bir XML belgesini ayrıştırmak yerine üretmek istersek ne olacak? Bunu Go'da nasıl yaparız? Tahmin edebileceğiniz gibi, `xml` paketi iki fonksiyon sunar: `Marshal` ve `MarshalIndent`. İkincisi, ürettiği XML belgesini otomatik olarak girintiler. Tanımları şöyledir:
```Go
func Marshal(v interface{}) ([]byte, error)
func MarshalIndent(v interface{}, prefix, indent string) ([]byte, error)
```
Bu fonksiyonların ikisinde de ilk argüman, üretilen XML veri akışını saklamak içindir.

Bunun nasıl çalıştığını görmek için bir örneğe bakalım:
```Go
package main

import (
    "encoding/xml"
    "fmt"
    "os"
)

type Servers struct {
    XMLName xml.Name `xml:"servers"`
    Version string   `xml:"version,attr"`
    Svs     []server `xml:"server"`
}

type server struct {
    ServerName string `xml:"serverName"`
    ServerIP   string `xml:"serverIP"`
}

func main() {
    v := &Servers{Version: "1"}
    v.Svs = append(v.Svs, server{"Shanghai_VPN", "127.0.0.1"})
    v.Svs = append(v.Svs, server{"Beijing_VPN", "127.0.0.2"})
    output, err := xml.MarshalIndent(v, "  ", "    ")
    if err != nil {
        fmt.Printf("hata: %v\n", err)
    }
    os.Stdout.Write([]byte(xml.Header))

    os.Stdout.Write(output)
}
```
Yukarıdaki örnek aşağıdaki bilgiyi ekrana basar:
```xml
<?xml version="1.0" encoding="UTF-8"?>
<servers version="1">
<server>
    <serverName>Shanghai_VPN</serverName>
    <serverIP>127.0.0.1</serverIP>
</server>
<server>
    <serverName>Beijing_VPN</serverName>
    <serverIP>127.0.0.2</serverIP>
</server>
</servers>
```
Daha önce belirttiğimiz gibi, kodumuzda `os.Stdout.Write([]byte(xml.Header))` satırının bulunmasının nedeni, hem `xml.MarshalIndent` hem de `xml.Marshal`'ın XML başlıklarını kendiliğinden basmamasıdır; bu yüzden XML belgelerini doğru üretebilmek için başlıkları açıkça yazdırmak zorundayız.

Burada `Marshal`'ın da `interface{}` türünde bir v parametresi aldığını görebiliyoruz. Peki bir XML belgesi üretilirken hangi kurallar geçerli? 

- v bir array ya da slice ise, tüm elemanları bir değer gibi basar.
- v bir pointer (işaretçi) ise, v'nin işaret ettiği içeriği basar; v nil olduğunda hiçbir şey basmaz.
- v bir interface ise, interface'i de aynı şekilde işler.
- v diğer türlerden biriyse, o türün değerini basar.

Peki `xml.Marshal` elemanların adına nasıl karar veriyor? Şu kuralları izler:

- v bir struct ise, adı XMLName tag'i içinde tanımlar.
- Alan adının XMLName, türünün ise xml.Name olması.
- Struct içindeki alan tag'i.
- Struct içindeki alan adı.
- Marshal edilen türün adı.

Ardından, son XML belgesini üretmek için tag'leri nasıl ayarlayacağımızı çözmemiz gerekiyor.

- XMLName basılmaz.
- Tag'i `"-"` içeren alanlar basılmaz.
- Bir tag `"name,attr"` içeriyorsa, nitelik adı olarak name'i, değer olarak da alanın değerini kullanır; yukarıdaki örnekteki `version` gibi.
- Bir tag `",attr"` içeriyorsa, nitelik adı olarak alanın adını, değer olarak da alanın değerini kullanır.
- Bir tag `",chardata"` içeriyorsa, eleman yerine karakter verisi basar.
- Bir tag `",innerxml"` içeriyorsa, ham değeri basar.
- Bir tag `",comment"` içeriyorsa, escape etmeden yorum olarak basar; bu yüzden değerinin içinde "--" bulunamaz.
- Bir tag `"omitempty"` içeriyorsa, alanın değeri sıfır değer olduğunda bu alanı atlar; buna false, 0, nil pointer ya da nil interface, sıfır uzunluklu array, slice, map ve string dahildir.
- Bir tag `"a>b>c"` içeriyorsa, a'nın b'yi, b'nin de c'yi içerdiği üç eleman basar; aşağıdaki koddaki gibi:
```xml
FirstName string   `xml:"name>first"`
LastName  string   `xml:"name>last"`

<name>
<first>Asta</first>
<last>Xie</last>
</name>
```
Struct tag'lerinin XML ile uğraşırken çok kullanışlı olduğunu fark etmişsinizdir; sonraki bölümlerde ele alacağımız diğer veri biçimleri için de aynısı geçerli. Struct tag'leriyle çalışmakta hâlâ sorun yaşıyorsanız, sonraki bölüme dalmadan önce bunlar hakkında biraz daha dokümantasyon okumanız iyi olur.

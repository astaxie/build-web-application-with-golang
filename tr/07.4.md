# 7.4 Şablonlar

## Şablon nedir?

Umarım MVC (Model, View, Controller) tasarım modelini biliyorsunuzdur: modeller veriyi işler, view'lar sonuçları gösterir, controller'lar da kullanıcı isteklerini karşılar. View tarafında birçok dinamik dil, statik HTML dosyalarının içine kod yazarak veri üretir. Örneğin JSP bunu `<%=....=%>`, PHP ise `<?php.....?>` gibi işaretler ekleyerek yapar.

Aşağıdaki görsel şablon mekanizmasını gösteriyor:
![](images/7.4.template.png?raw=true)

Şekil 7.1 Şablon mekanizması

Web uygulamalarının istemcilere döndürdüğü içeriğin büyük kısmı statiktir; dinamik kısımlar genellikle çok küçüktür. Örneğin bir sayfayı ziyaret etmiş kullanıcıların listesini göstermeniz gerekiyorsa yalnızca kullanıcı adı dinamiktir. Listenin biçimi hep aynı kalır. Gördüğünüz gibi şablonlar, statik içeriği yeniden kullanmak için oldukça faydalıdır.

## Go'da şablonlar

Go'da şablonlarla çalışmamıza yardımcı olan `template` paketi var. `Parse`, `ParseFile` ve `Execute` gibi fonksiyonları kullanarak şablonları düz metinden ya da dosyalardan yükleyebilir, ardından şekil 7.1'de gösterildiği gibi dinamik kısımları değerlendirebiliriz.

Örnek:
```Go
func handler(w http.ResponseWriter, r *http.Request) {
	t := template.New("some template") // Bir şablon oluştur.
	t, _ = t.ParseFiles("tmpl/welcome.html", nil)  // Şablon dosyasını ayrıştır.
	user := GetUser() // Geçerli kullanıcı bilgisini al.
	t.Execute(w, user)  // birleştir.
}
```
Gördüğünüz gibi Go'da şablonları kullanmak, yüklemek ve içlerine veri yerleştirmek tıpkı diğer programlama dillerindeki gibi çok kolay.

Kolaylık olsun diye örneklerimizde şu kuralları kullanacağız:

- `ParseFiles` yerine `Parse` kullanacağız; çünkü `Parse` içeriği doğrudan string üzerinden test edebiliyor, böylece fazladan dosyaya ihtiyacımız olmuyor.
- Her örnekte `handler` yerine `main` kullanacağız.
- `http.ResponseWriter` yerine `os.Stdout` kullanacağız; çünkü `os.Stdout` da `io.Writer` interface'ini uyguluyor.

## Şablona veri yerleştirme

Şablonların nasıl ayrıştırılıp işleneceğini az önce gösterdik. Şimdi bir adım öteye gidip şablonlarımıza veri yerleştirelim. Go'da her şablon bir nesnedir; peki şablonlara alanları nasıl yerleştireceğiz?

### Alanlar

Go'da bir şablon içinde işlenmesini istediğiniz her alan `{{}}` içine konulmalıdır. `{{.}}`, geçerli nesnenin kısaltmasıdır ve Java ya da C++'taki karşılığına benzer. Geçerli nesnenin alanlarına erişmek istiyorsanız `{{.FieldName}}` yazmalısınız. Şablonlar içinde yalnızca dışarı açık (exported) alanlara erişilebileceğini unutmayın. İşte bir örnek:
```Go
package main

import (
	"html/template"
	"os"
)

type Person struct {
	UserName string
}

func main() {
	t := template.New("fieldname example")
	t, _ = t.Parse("merhaba {{.UserName}}!")
	p := Person{UserName: "Astaxie"}
	t.Execute(os.Stdout, p)
}
```
Yukarıdaki örnek doğru biçimde `merhaba Astaxie` çıktısını verir; fakat struct'ımızı biraz değiştirirsek şu hata ortaya çıkar:
```Go
type Person struct {
	UserName string
	email	string  // Alan dışarı açık değil.
}

t, _ = t.Parse("merhaba {{.UserName}}! {{.email}}")
```
Kodun bu kısmı derlenmeyecektir; çünkü dışarı açık olmayan bir alana erişmeye çalışıyoruz. Ancak var olmayan bir alanı kullanmaya çalışırsak Go hata vermek yerine yalnızca boş bir string basar.

Bir şablonda `{{.}}` yazdırırsanız Go, arka planda `fmt` paketini çağırarak bu nesnenin biçimlendirilmiş string hâlini basar.

### İç içe alanlar

Artık bir alanın nasıl basılacağını biliyoruz. Peki alanın kendisi bir nesneyse ve onun da kendi alanları varsa ne olacak? Hepsini tek bir döngüde nasıl basarız? Tam da bu iş için `{{with …}}…{{end}}` ve `{{range …}}{{end}}` yapılarını kullanabiliriz.

- {% raw %}`{{range}}`{% endraw %} tıpkı Go'daki range gibidir.
- {% raw %}`{{with}}`{% endraw %} aynı nesne adını bir kez yazmanızı ve onun kısaltması olarak `.` kullanmanızı sağlar ( ***VB'deki `with` yapısına benzer*** ).

Daha fazla örnek:
```Go
package main

import (
	"html/template"
	"os"
)

type Friend struct {
	Fname string
}

type Person struct {
	UserName string
	Emails   []string
	Friends  []*Friend
}

func main() {
	f1 := Friend{Fname: "minux.ma"}
	f2 := Friend{Fname: "xushiwei"}
	t := template.New("fieldname example")
	t, _ = t.Parse(`merhaba {{.UserName}}!
			{{range .Emails}}
				bir e-posta {{.}}
			{{end}}
			{{with .Friends}}
			{{range .}}
				arkadaşımın adı {{.Fname}}
			{{end}}
			{{end}}
			`)
	p := Person{UserName: "Astaxie",
		Emails:  []string{"astaxie@beego.me", "astaxie@gmail.com"},
		Friends: []*Friend{&f1, &f2}}
	t.Execute(os.Stdout, p)
}
```
### Koşullar

Şablonlarda koşulları denetlemeniz gerekiyorsa, tıpkı sıradan Go programlarında yaptığınız gibi `if-else` söz dizimini kullanabilirsiniz. Pipeline boşsa `if` için öntanımlı değer `false` olur. Aşağıdaki örnek şablonlarda `if-else` kullanımını gösteriyor:
```Go
package main

import (
	"os"
	"text/template"
)

func main() {
	tEmpty := template.New("template test")
	tEmpty = template.Must(tEmpty.Parse("Boş pipeline if örneği: {{if ``}} çıktıya basılmayacak. {{end}}\n"))
	tEmpty.Execute(os.Stdout, nil)

	tWithValue := template.New("template test")
	tWithValue = template.Must(tWithValue.Parse("Boş olmayan pipeline if örneği: {{if `anything`}} çıktıya basılacak. {{end}}\n"))
	tWithValue.Execute(os.Stdout, nil)

	tIfElse := template.New("template test")
	tIfElse = template.Must(tIfElse.Parse("if-else örneği: {{if `anything`}} if kısmı {{else}} else kısmı.{{end}}\n"))
	tIfElse.Execute(os.Stdout, nil)
}
```
Gördüğünüz gibi şablonlarda `if-else` kullanmak çok kolay.

**Dikkat** if içinde koşul ifadeleri KULLANAMAZSINIZ; örneğin `.Mail=="astaxie@gmail.com"` yazamazsınız. Yalnızca boolean değerler kabul edilir.

### pipeline'lar

Unix kullanıcıları `ls | grep "beego"` gibi kullanımlardaki `pipe` operatörüne aşinadır. Bu komut dosyaları filtreler ve yalnızca `beego` kelimesini içerenleri gösterir. Go şablonlarında hoşuma giden şeylerden biri de pipe'ları desteklemeleri. `{{}}` içindeki her şey pipeline'ların verisi olabilir. Yukarıda kullandığımız e-posta adresi uygulamamızı XSS saldırılarına açık hâle getirebilir. Peki bu sorunu pipe kullanarak nasıl çözeriz?

	{{. | html}}

E-posta gövdesini HTML'e escape etmek için bu yöntemi kullanabiliriz. Bir Unix komutu yazmaya oldukça benziyor ve şablon fonksiyonlarında kullanmak için de elverişli.

### Şablon değişkenleri

Bazen şablonlarda yerel değişkenler kullanmamız gerekir. Bunları `with`, `range` ve `if` anahtar kelimeleriyle birlikte kullanabiliriz; kapsamları bu anahtar kelimeler ile `{{end}}` arasındadır. Global bir değişken tanımlama örneği şöyle:

	$variable := pipeline

Daha fazla örnek:

	{{with $x := "output" | printf "%q"}}{{$x}}{{end}}
	{{with $x := "output"}}{{printf "%q" $x}}{{end}}
	{{with $x := "output"}}{{$x | printf "%q"}}{{end}}

### Şablon fonksiyonları

Go, şablonlardaki çıktıyı biçimlendirmek için `fmt` paketini kullanır; ama bazen başka bir şey yapmamız gerekir. Örneğin şu senaryoyu düşünün: e-posta adresimizdeki `@` işaretini `at` ile değiştirmek istiyoruz, yani `astaxie at beego.me` biçiminde. Bu noktada özelleştirilmiş bir fonksiyon yazmamız gerekir.

Her şablon fonksiyonunun benzersiz bir adı vardır ve Go programınızdaki bir fonksiyonla şu şekilde ilişkilendirilir:

	type FuncMap map[string]interface{}

Diyelim ki Go programımızda `EmailDealWith` fonksiyonuyla ilişkilendirilmiş bir `emailDeal` şablon fonksiyonumuz var. Bu fonksiyonu kaydetmek için şu kodu kullanabiliriz:

	t = t.Funcs(template.FuncMap{"emailDeal": EmailDealWith})

`EmailDealWith` tanımı:

	func EmailDealWith(args …interface{}) string

Örnek:
```Go
package main

import (
	"fmt"
	"html/template"
	"os"
	"strings"
)

type Friend struct {
	Fname string
}

type Person struct {
	UserName string
	Emails   []string
	Friends  []*Friend
}

func EmailDealWith(args ...interface{}) string {
	ok := false
	var s string
	if len(args) == 1 {
		s, ok = args[0].(string)
	}
	if !ok {
		s = fmt.Sprint(args...)
	}
	// @ işaretini bul
	substrs := strings.Split(s, "@")
	if len(substrs) != 2 {
		return s
	}
	// @ işaretini " at " ile değiştir
	return (substrs[0] + " at " + substrs[1])
}

func main() {
	f1 := Friend{Fname: "minux.ma"}
	f2 := Friend{Fname: "xushiwei"}
	t := template.New("fieldname example")
	t = t.Funcs(template.FuncMap{"emailDeal": EmailDealWith})
	t, _ = t.Parse(`merhaba {{.UserName}}!
				{{range .Emails}}
					bir e-posta {{.|emailDeal}}
				{{end}}
				{{with .Friends}}
				{{range .}}
					arkadaşımın adı {{.Fname}}
				{{end}}
				{{end}}
				`)
	p := Person{UserName: "Astaxie",
		Emails:  []string{"astaxie@beego.me", "astaxie@gmail.com"},
		Friends: []*Friend{&f1, &f2}}
	t.Execute(os.Stdout, p)
}
```
Yerleşik şablon fonksiyonlarının listesi şöyle:
```Go
var builtins = FuncMap{
	"and":      and,
	"call":     call,
	"html":     HTMLEscaper,
	"index":    index,
	"js":       JSEscaper,
	"len":      length,
	"not":      not,
	"or":       or,
	"print":    fmt.Sprint,
	"printf":   fmt.Sprintf,
	"println":  fmt.Sprintln,
	"urlquery": URLQueryEscaper,
}

```
## Must

`template` paketinde şablonları doğrulamak için `Must` adında bir fonksiyon vardır; süslü parantezlerin, yorumların ve değişkenlerin eşleşip eşleşmediğini denetler. Gelin `Must` için bir örneğe bakalım:
```Go
package main

import (
	"fmt"
	"text/template"
)

func main() {
	tOk := template.New("first")
	template.Must(tOk.Parse(" biraz statik metin /* ve bir yorum */"))
	fmt.Println("Birincisi düzgün ayrıştırıldı.")

	template.Must(template.New("second").Parse("biraz statik metin {{ .Name }}"))
	fmt.Println("İkincisi düzgün ayrıştırıldı.")

	fmt.Println("Sıradaki hata vermeli.")
	tErr := template.New("check parse error with Must")
	template.Must(tErr.Parse(" biraz statik metin {{ .Name }"))
}
```
Çıktı:

	Birincisi düzgün ayrıştırıldı.
	İkincisi düzgün ayrıştırıldı.
	Sıradaki hata vermeli.
	panic: template: check parse error with Must:1: unexpected "}" in command

## İç içe şablonlar

Tıpkı çoğu web uygulamasında olduğu gibi, şablonların bazı kısımları başka şablonlarda yeniden kullanılabilir; bir blogun başlık ve alt bilgi kısımları gibi. `header`, `content` ve `footer` bölümlerini alt şablon olarak tanımlayabilir ve Go'da şu söz dizimiyle bildirebiliriz:

	{{define "sub-template"}}content{{end}}

Alt şablon şu söz dizimiyle çağrılır:

	{{template "sub-template"}}

İşte eksiksiz bir örnek: `templates` dizininde `header.tmpl`, `content.tmpl` ve `footer.tmpl` adlı üç dosyamız olduğunu varsayalım; dizini okuyup dosya adlarını bir string dizisinde saklayacak, sonra da bu diziyi dosyaları ayrıştırmak için kullanacağız.

Ana şablon:
```html
{% raw %}
//header.tmpl
{{define "header"}}
<html>
<head>
	<title>Buraya bir şeyler</title>
</head>
<body>
{{end}}

//content.tmpl
{{define "content"}}
{{template "header"}}
<h1>Burada iç içe</h1>
<ul>
	<li>İç içe kullanım</li>
	<li>Şablon çağırma</li>
</ul>
{{template "footer"}}
{{end}}

//footer.tmpl
{{define "footer"}}
</body>
</html>
{{end}}

//Alt şablon kullanırken her alt şablon dosyasını ayrıştırdığınızdan emin olun,
//aksi hâlde derleyici {{template "header"}} satırını okuduğunda yerine ne koyacağını anlayamaz

{% endraw %}
```
Kod:
```Go
package main

import (
	"fmt"
	"os"
	"io/ioutil"
	"text/template"
	"strings"
)

var templates *template.Template

func main() {
	var allFiles []string
	files, err := ioutil.ReadDir("./templates")
	if err != nil {
		fmt.Println(err)
	}
	for _, file := range files {
		filename := file.Name()
		if strings.HasSuffix(filename, ".tmpl") {
			allFiles = append(allFiles, "./templates/"+filename)
		}
	}

	templates, err = template.ParseFiles(allFiles...) #'templates' dizinindeki tüm .tmpl dosyalarını ayrıştırır

	s1 := templates.Lookup("header.tmpl")
	s1.ExecuteTemplate(os.Stdout, "header", nil)
	fmt.Println()
	s2 := templates.Lookup("content.tmpl")
	s2.ExecuteTemplate(os.Stdout, "content", nil)
	fmt.Println()
	s3 := templates.Lookup("footer.tmpl")
	s3.ExecuteTemplate(os.Stdout, "footer", nil)
	fmt.Println()
	s3.Execute(os.Stdout, nil)
}
```
Burada `template.ParseFiles`'ın iç içe geçmiş tüm şablonları önbelleğe ayrıştırdığını ve `{{define}}` ile tanımlanan her şablonun birbirinden bağımsız olduğunu görüyoruz. Bunlar map benzeri bir yapıda saklanır; şablon adları anahtar, şablon gövdeleri ise değerdir. Sonrasında ilgili alt şablonları çalıştırmak için `ExecuteTemplate` kullanabiliriz; böylece header ve footer bağımsız kalır, content ise ikisini birden içerir. Dikkat edin: `s1.Execute` çalıştırmayı denersek hiçbir çıktı üretilmez, çünkü ortada öntanımlı bir alt şablon yoktur.

`{{define}}` kullanmak istemiyorsanız, alt şablonun adını taşıyan bir metin dosyası oluşturmanız yeterli; örneğin `_head.tmpl` projeniz boyunca kullanacağınız bir alt şablonsa bu dosyayı templates dizininde oluşturun ve normal söz dizimini kullanın. Lookup önbelleği temelde, her istekte dosyayı yeniden okumak zorunda kalmayasınız diye vardır; çünkü öyle yaparsanız, kod tabanı yeniden yazılmadıkça değişmeyecek bir dosyayı okumak için bir sürü kaynak harcarsınız. Her HTTP GET isteğinde şablon dosyalarını ayrıştırmak mantıklı değildir; bu yüzden dosyaları bir kez ayrıştırıp, veriyi göstermek için şablona ihtiyacımız olduğunda önbellek üzerinde `Lookup()` yapma tekniği kullanılır.

Aynı kümedeki şablonlar birbirini tanır; ancak her kümeyi tek tek ayrıştırmanız gerekir.

Bazen şablonları bağlama göre değiştirmek istersiniz; örneğin bir `_head.html` dosyanız var ve değeri, yüklediğiniz veriye göre doldurulması gereken bir başlığınız olabilir. Söz gelimi bir yapılacaklar listesi yöneticisinde `pending`, `completed`, `deleted` şeklinde üç kategoriniz olabilir. Bunun için şöyle bir if ifadeniz olduğunu varsayın
```html
<title>{{if eq .Navigation "pending"}} Görevler
    {{ else if eq .Navigation "completed"}}Tamamlanan
    {{ else if eq .Navigation "deleted"}}Silinen
    {{ else if eq .Navigation "edit"}} Düzenle
    {{end}}
</title>
```
Not: Go şablonları karşılaştırma yaparken Polonya notasyonunu izler; yani önce operatörü, sonra karşılaştırma değerini ve karşılaştırılacak değeri verirsiniz. else if kısmı ise gayet anlaşılır

Genellikle şablonu çalıştırırken ona geçirdiğimiz bağlam (context) değişkeni üzerinde dönmek için bir `{{ range }}` operatörü kullanırız; şöyle:
```Go
    //views paketinde bulunur
    context := db.GetTasks("pending") //silinmemiş notları istediğinizde true olur
    homeTemplate.Execute(w, context)
```	
Bağlam nesnesini veritabanından bir struct nesnesi olarak alırız; tanımı aşağıdaki gibidir
```Go
//Task, görevleri tanımlamak için kullanılan struct'tır
type Task struct {
   	Id      int
    Title   string
    Content string
    Created string
}
//Context, şablonlara geçirilen struct'tır
type Context struct {
    Tasks      []Task
    Navigation string
    Search     string
    Message    string
}

//database paketinde bulunur
var task []types.Task
var context types.Context
context = types.Context{Tasks: task, Navigation: status}

//Bu satır, bağlamın view'a geri döndürüldüğü database paketindedir.
```
Şablonlarımızda task dizisini ve Navigation alanını kullanıyoruz; Navigation'ı şablonda nasıl kullandığımızı gördük,
şimdi de asıl task dizisini şablonumuzda nasıl kullanacağımıza bakacağız.

Burada `{{ if .Tasks }}` ile önce, şablonu çalıştırırken ona geçirdiğimiz bağlam nesnesinin Tasks alanının boş olup
olmadığını denetliyoruz. Boş değilse Task'ın başlığını ve içeriğini doldurmak için o dizi üzerinde döneceğiz. Aşağıdaki
örnek, bir şablonda dizi üzerinde dönme konusunda çok önemlidir; işe Range operatörüyle başlıyoruz, ardından o struct'ın
herhangi bir üyesini `{{.Name}}` biçiminde verebiliyoruz. Benim Task yapımda bir Title ve bir Content var (T ve C
harflerinin büyük olduğuna dikkat edin; bunlar dışarı açık adlardır ve private olmalarını istemiyorsanız büyük harfle
başlamaları gerekir).
```Go
{{ range .Tasks }}
    {{ .Title }}
    {{ .Content }}
{{ end }}
```
Bu kod bloğu, Task dizisindeki her başlığı ve içeriği basacaktır. Aşağıda github.com/thewhitetulip/Tasks projesinin home.html şablonundan alınmış eksiksiz bir örnek var.
```html
<div class="timeline">
{{ if .Tasks}} {{range .Tasks}}
<div class="note">
    <p class="noteHeading">{{.Title}}</p>
    <hr>
    <p class="noteContent">{{.Content}}</p>
    </ul>
    </span>
</div>
{{end}} {{else}}
<div class="note">
    <p class="noteHeading">Burada hiç görev yok</p>
    <p class="notefooter">
    Yeni görev oluştur<button class="floating-action-icon-add" > buradan </button> </p>
</div>
{{end}}
```

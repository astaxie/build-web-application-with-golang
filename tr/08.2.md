# 8.2 WebSocket

WebSocket, HTML5'in önemli bir özelliğidir. Tarayıcı tabanlı uzak soketleri hayata geçirir ve bu sayede tarayıcılar sunucularla tam çift yönlü (full-duplex) iletişim kurabilir. Firefox, Google Chrome ve Safari gibi başlıca tarayıcılar bu WebSocket desteğini sağlar.

WebSocket doğmadan önce, anlık mesajlaşma servislerinde sıklıkla "yuvarlanan yoklama (roll polling)" kullanılırdı; bu yöntemde istemciler periyodik olarak HTTP istekleri gönderir. Sunucu ardından istemcilere en güncel veriyi döndürür. Bu yöntemin dezavantajı, istemcilerin sunucuya sürekli çok sayıda istek göndermesini gerektirmesi ve bunun büyük miktarda bant genişliği tüketmesidir.

WebSocket, bağlantı kurmak için tarayıcı ile sunucu arasında gereken el sıkışma sayısını yalnızca bire indiren özel bir başlık türü kullanır. Bu bağlantı, ömrü boyunca aktif kalır ve geleneksel TCP soketlerinde olduğu gibi bu bağlantıdan veri yazmak veya okumak için JavaScript kullanabilirsiniz. Gerçek zamanlı web geliştirmeyle ilgili birçok baş belasını çözer ve geleneksel HTTP'ye kıyasla şu avantajlara sahiptir:

- Tek bir web istemcisi için yalnızca bir TCP bağlantısı.
- WebSocket sunucuları web istemcilerine veri gönderebilir (push).
- Veri iletim yükünü azaltan hafif başlık.

WebSocket URL'leri ws:// veya wss:// (SSL) ile başlar. Aşağıdaki şekil WebSocket'in iletişim sürecini gösterir. El sıkışma protokolünün bir parçası olarak sunucuya belirli bir HTTP başlığı gönderilir ve bağlantı kurulur. Ardından sunucular veya istemciler WebSocket üzerinden JavaScript aracılığıyla veri gönderebilir veya alabilir. Bu soket, veriyi asenkron olarak almak için bir olay işleyicisi (event handler) tarafından kullanılabilir.

## WebSocket prensipleri

WebSocket protokolü aslında oldukça basittir. İlk el sıkışma başarıyla tamamlandıktan sonra bir bağlantı kurulur. Sonraki veri iletişimlerinin tamamı "\x00" ile başlar ve "\xFF" ile biter. Bu önek ve sonek istemciler tarafından görülmez, çünkü WebSocket her iki ucu da keserek ham veriyi otomatik olarak sağlar.

WebSocket bağlantıları tarayıcılar tarafından istenir ve sunucular tarafından yanıtlanır; bunun ardından bağlantı kurulur. Bu sürece genellikle "el sıkışma (handshaking)" denir.

"Sec-WebSocket-key" rastgele üretilir, tahmin etmiş olabileceğiniz gibi, ve base64 ile kodlanmıştır. Sunucular bir isteği kabul ettikten sonra bu anahtarı sabit bir dizeye eklemelidir:

	258EAFA5-E914-47DA-95CA-C5AB0DC85B11

Örneğin `f7cb4ezEAl6C3wRaU6JORA==` değerimiz olsun, o zaman şunu elde ederiz:

	f7cb4ezEAl6C3wRaU6JORA==258EAFA5-E914-47DA-95CA-C5AB0DC85B11

Bu değerin ikili (binary) değerini hesaplamak için sha1 kullanın ve ardından base64 ile kodlayın. Böylece şunu elde ederiz:

	rE91AJhfC+6JdVcVXOGJEADEJdQ=

Bunu `Sec-WebSocket-Accept` yanıt başlığının değeri olarak kullanın.

## Go'da WebSocket

Go standart kütüphanesi WebSocket'i desteklemez. Ancak `go.net`'in bir alt paketi olan `websocket` paketi bunu destekler ve resmi olarak bakımı yapılıp desteklenmektedir.

Bu paketi kurmak için `go get` kullanın:

	go get golang.org/x/net/websocket

WebSocket'in hem istemci hem de sunucu tarafı vardır. Kullanıcının istemci tarafında bazı bilgiler girdiği ve bunu WebSocket üzerinden sunucuya gönderdiği, ardından sunucunun da bilgiyi istemciye geri gönderdiği (push) basit bir örneğe bakalım.

İstemci kodu:

	<html>
	<head></head>
	<body>
		<script type="text/javascript">
			var sock = null;
			var wsuri = "ws://127.0.0.1:1234";

			window.onload = function() {

				console.log("onload");

				sock = new WebSocket(wsuri);

				sock.onopen = function() {
					console.log("connected to " + wsuri);
				}

				sock.onclose = function(e) {
					console.log("connection closed (" + e.code + ")");
				}

				sock.onmessage = function(e) {
					console.log("message received: " + e.data);
				}
			};

			function send() {
				var msg = document.getElementById('message').value;
				sock.send(msg);
			};
		</script>
		<h1>WebSocket Echo Test</h1>
		<form>
			<p>
				Message: <input id="message" type="text" value="Hello, world!">
			</p>
		</form>
		<button onclick="send();">Send Message</button>
	</body>
	</html>

Görebileceğiniz gibi, istemci tarafı JavaScript fonksiyonlarını kullanarak bir bağlantı kurmak çok kolaydır. `onopen` olayı, yukarıda bahsedilen el sıkışma süreci başarıyla tamamlandıktan sonra tetiklenir. Bu, istemciye bağlantının başarıyla kurulduğunu bildirir. Bir bağlantı açmaya çalışan istemciler genellikle şu dört olaya bağlanır:

- 1）onopen: bağlantı kurulduktan sonra tetiklenir.
- 2）onmessage: bir mesaj alındıktan sonra tetiklenir.
- 3）onerror: bir hata oluştuktan sonra tetiklenir.
- 4）onclose: bağlantı kapandıktan sonra tetiklenir.

Sunucu kodu:

	package main

	import (
		"golang.org/x/net/websocket"
		"fmt"
		"log"
		"net/http"
	)

	func Echo(ws *websocket.Conn) {
		var err error

		for {
			var reply string

			if err = websocket.Message.Receive(ws, &reply); err != nil {
				fmt.Println("Can't receive")
				break
			}

			fmt.Println("Received back from client: " + reply)

			msg := "Received:  " + reply
			fmt.Println("Sending to client: " + msg)

			if err = websocket.Message.Send(ws, msg); err != nil {
				fmt.Println("Can't send")
				break
			}
		}
	}

	func main() {
		http.Handle("/", websocket.Handler(Echo))

		if err := http.ListenAndServe(":1234", nil); err != nil {
			log.Fatal("ListenAndServe:", err)
		}
	}

Bir istemci kullanıcı girdisi bilgisini `Send` ettiğinde, sunucu bunu `Receive` eder ve yanıtı döndürmek için tekrar `Send` kullanır.

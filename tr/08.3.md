# 8.3 REST

REST günümüzde internetteki en popüler yazılım mimarisidir çünkü iyi tanımlanmış, sıkı standartlar üzerine kuruludur ve anlaşılması ile genişletilmesi kolaydır. Giderek daha fazla web sitesi tasarımlarını REST üzerine kuruyor. Bu bölümde, REST mimarisinin Go'da nasıl uygulandığına yakından bakacağız ve (umarım) bunu kendi yararımıza nasıl kullanacağımızı öğreneceğiz.

## REST nedir?

REST (REpresentational State Transfer) kavramının ilk beyanı, aynı zamanda HTTP protokolünün ortak kurucusu olan Roy Thomas Fielding'in 2000 yılındaki doktora tezinde yapılmıştır. Bu tez mimarinin kısıtlarını ve ilkelerini belirtir ve bu mimariyle uygulanan her şeye RESTful sistem denilebilir.

REST'in ne olduğunu anlamadan önce, aşağıdaki kavramları ele almamız gerekiyor:

- Kaynaklar (Resources)

  	REST, Sunum Katmanı Durum Transferi'dir; burada sunum katmanı aslında kaynak sunum katmanıdır.

  	Peki kaynak nedir? Resimler, dökümanlar veya videolar vb. hepsi kaynak örnekleridir ve bir URI ile bulunabilirler.

- Temsil (Representation)

	Kaynaklar, sunum katmanı içinde çeşitli şekillerde gösterilebilen belirli bilgi varlıklarıdır. Örneğin, bir TXT dökümanı HTML, JSON, XML vb. olarak temsil edilebilir; bir resim ise jpg, png vb. olarak temsil edilebilir.

	Kaynakları tanımlamak için URI'ler kullanılır, ancak belirli tezahürlerini nasıl belirleriz? Bunun için HTTP istek başlığındaki Accept ve Content-Type alanlarına başvurulur; bu iki alan sunum katmanını tanımlar.

- Durum Transferi (State Transfer)

	Bir web sitesinin herhangi bir sayfasını her ziyaret edişinizde istemci ile sunucu arasında etkileşimli bir süreç başlatılır. Bu süreç boyunca, mevcut sayfa durumuyla ilgili belirli verilerin saklanması gerekir. Ancak, HTTP'nin durumsuz (stateless) bir protokol olduğunu hatırlayacaksınız! Bu istemci durumunu sunucu tarafında saklamamız gerektiği açıktır. Buradan çıkan sonuç şudur: eğer bir istemci bazı verileri değiştirir ve değişiklikleri kalıcı hale getirmek isterse, sunucu tarafını yeni durum hakkında bilgilendirecek bir yol olmalıdır.

	Çoğu zaman istemciler, sunuculara durum değişikliklerini HTTP kullanarak bildirir. Bunu yapmak için dört işlemleri vardır:

	-GET kaynakları elde etmek için kullanılır
	-POST kaynak oluşturmak veya güncellemek için kullanılır
	-PUT kaynakları günceller
	-DELETE kaynakları siler

Yukarıdakileri özetlersek:

- （1）Her URI bir kaynağı temsil eder.
- （2）İstemciler ile sunucular arasında kaynak transferi için bir temsil katmanı vardır.
- （3）İstemciler, uzak kaynaklar üzerinde işlem yapmalarını sağlayan "Sunum Katmanı Durum Transferi"ni uygulamak için dört HTTP methodunu kullanır.

REST'i uygulayan web uygulamalarının en önemli ilkesi, istemciler ile sunucular arasındaki etkileşimin durumsuz olmasıdır; her istek, gereken tüm bilgiyi kendi içinde barındırmalıdır. Sunucular, istemcilere bildirilmeden herhangi bir anda yeniden başlatılabilmelidir. Ayrıca, isteklere aynı hizmetin herhangi bir sunucusu tarafından yanıt verilebilir, bu da bulut bilişim için idealdir. Son olarak, durumsuz olduğu için istemciler performansı artırmak amacıyla veriyi önbelleğe alabilir.

REST'in bir diğer önemli ilkesi sistem katmanlandırmasıdır; bu, bir katmandaki bileşenlerin başka bir katmandaki bileşenlerle doğrudan etkileşime giremeyeceği anlamına gelir. Bu, sistem karmaşıklığını sınırlayabilir ve alttaki bileşenlerin bağımsızlığını teşvik edebilir.

## RESTful uygulaması

Go, REST için doğrudan destek sunmaz, ancak RESTful web uygulamalarının hepsi HTTP tabanlı olduğundan, bunu kendimiz uygulamak için `net/http` paketini kullanabiliriz. Elbette, REST'i tam olarak uygulayabilmeden önce bazı değişiklikler yapmamız gerekecek.

REST, kaynaklarla ilgili gereken etkileşime bağlı olarak farklı methodlar kullanır. Mevcut birçok uygulama RESTful olduğunu iddia eder ama gerçekte REST'i uygulamazlar. Bu uygulamaları, hangi HTTP methodlarını uyguladıklarına bağlı olarak birkaç seviyeye ayıracağım.

![](images/8.3.rest3.png?raw=true)

Şekil 8.7 REST'in seviyeleri.

Yukarıdaki resim, günümüzde REST'te uygulanan üç seviyeyi göstermektedir. Kendi uygulamalarınızı geliştirirken REST'in tüm kural ve kısıtlarını takip etmemeyi tercih edebilirsiniz çünkü bazen bu kurallar her duruma uygun düşmez. RESTful web uygulamaları `DELETE` ve `PUT` dahil her HTTP methodunu kullanır, ama birçok durumda HTTP istemcileri yalnızca `GET` ve `POST` istekleri gönderebilir.

- HTML standardı, istemcilerin bağlantılar ve formlar aracılığıyla `GET` ve `POST` istekleri göndermesine izin verir. AJAX desteği olmadan `PUT` veya `DELETE` isteği göndermek mümkün değildir.
- Bazı güvenlik duvarları `PUT` ve `DELETE` isteklerini engeller ve istemcilerin bunları gerçekleştirmek için POST kullanması gerekir. Tam anlamıyla RESTful servisler, orijinal HTTP methodlarını bulup geri yüklemekle sorumludur.

POST isteklerimize gizli bir `_method` alanı ekleyerek `PUT` ve `DELETE` isteklerini simüle edebiliriz, ancak bu isteklerin işlenmeden önce sunucu tarafında dönüştürülmesi gerekir. Kendi uygulamalarımda REST arayüzlerini uygulamak için bu iş akışını kullanıyorum. Standart RESTful arayüzler Go'da kolayca uygulanabilir; aşağıdaki örnek bunu göstermektedir:

```Go

	package main

	import (
		"fmt"
		"github.com/julienschmidt/httprouter"
		"log"
		"net/http"
	)

	func Index(w http.ResponseWriter, r *http.Request, _ httprouter.Params) {
		fmt.Fprint(w, "Welcome!\n")
	}

	func Hello(w http.ResponseWriter, r *http.Request, ps httprouter.Params) {
		fmt.Fprintf(w, "hello, %s!\n", ps.ByName("name"))
	}

	func getuser(w http.ResponseWriter, r *http.Request, ps httprouter.Params) {
		uid := ps.ByName("uid")
		fmt.Fprintf(w, "you are get user %s", uid)
	}

	func modifyuser(w http.ResponseWriter, r *http.Request, ps httprouter.Params) {
		uid := ps.ByName("uid")
		fmt.Fprintf(w, "you are modify user %s", uid)
	}

	func deleteuser(w http.ResponseWriter, r *http.Request, ps httprouter.Params) {
		uid := ps.ByName("uid")
		fmt.Fprintf(w, "you are delete user %s", uid)
	}

	func adduser(w http.ResponseWriter, r *http.Request, ps httprouter.Params) {
		// uid := r.FormValue("uid")
		uid := ps.ByName("uid")
		fmt.Fprintf(w, "you are add user %s", uid)
	}

	func main() {
		router := httprouter.New()
		router.GET("/", Index)
		router.GET("/hello/:name", Hello)

		router.GET("/user/:uid", getuser)
		router.POST("/adduser/:uid", adduser)
		router.DELETE("/deluser/:uid", deleteuser)
		router.PUT("/moduser/:uid", modifyuser)

		log.Fatal(http.ListenAndServe(":8080", router))
	}

```

Bu örnek kod, çok temel bir REST uygulamasının nasıl yazılacağını gösterir. Kaynaklarımız kullanıcılardır ve farklı methodlar için farklı fonksiyonlar kullanıyoruz. Burada, `github.com/julienschmidt/httprouter` adlı üçüncü parti bir paketi içe aktardık. Özel bir yönlendirici uygulamayı önceki bölümlerde zaten ele almıştık - `julienschmidt/httprouter` paketi, RESTful mimariyi uygulamak için oldukça kullanışlı olan bazı çok pratik yönlendirici eşleme kuralları uygular. Görebileceğiniz gibi, REST aynı kaynağın farklı HTTP methodları için farklı mantık uygulamanızı gerektirir.

## Özet

REST, WWW ile geçmişteki başarılı deneyimler üzerine inşa edilen bir web mimarisi tarzıdır: durumsuzluk, kaynak merkezlilik, HTTP ve URI protokollerinin tam kullanımı ve birleşik arayüzlerin sağlanması. Bu üstün tasarım düşünceleri, REST'in en popüler web servisleri standardı haline gelmesini sağlamıştır. Bir bakıma, URI'yi vurgulayarak ve HTTP gibi erken İnternet standartlarından yararlanarak REST, büyük ve ölçeklenebilir web uygulamalarının önünü açmıştır. Şu an, Go'nun REST için sağladığı destek hâlâ oldukça temel düzeydedir. Ancak özel yönlendirme kuralları uygulayarak ve her HTTP istek türü için farklı istek işleyicileri tanımlayarak, Go web uygulamalarımızda RESTful mimariyi gerçekleştirebiliriz.

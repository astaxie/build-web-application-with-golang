# 8.4 RPC

Önceki bölümlerde soketler ve HTTP tabanlı ağ uygulamalarının nasıl yazılacağından bahsettik. Her ikisinin de "bilgi alışverişi" modelini kullandığını öğrendik; bu modelde istemciler istek gönderir, sunucular ise bu isteklere yanıt verir. Bu tür veri alışverişi, her iki tarafın da birbiriyle iletişim kurabilmesi için belirli bir biçime dayanır. Ancak birçok bağımsız uygulama bu modeli kullanmaz; bunun yerine servisleri sanki normal fonksiyonlarmış gibi çağırır.

RPC, ağ sistemleri için bir fonksiyon çağırma modu olması amacıyla tasarlanmıştır. İstemciler RPC'leri yerel fonksiyonları çağırır gibi çalıştırır; farkı, fonksiyon parametrelerini paketleyip ağ üzerinden sunucuya göndermeleridir. Sunucu bu parametreleri açıp isteği işleyebilir ve sonuçları istemciye geri döndürür.

Bilgisayar biliminde, uzak yordam çağrısı (remote procedure call, RPC), bir bilgisayar programının, programcının bu uzak etkileşimin ayrıntılarını açıkça kodlamasına gerek kalmadan başka bir adres alanında (genellikle paylaşılan bir ağ üzerindeki başka bir bilgisayarda) bir alt yordamın veya yordamın çalıştırılmasını sağlayan bir süreçler arası iletişim türüdür. Yani programcı, alt yordam çalıştırılan programa yerel olsa da uzak olsa da esasen aynı kodu yazar. Söz konusu yazılım nesne yönelimli ilkeler kullandığında, RPC "uzak çağırma" ya da "uzak method çağırma" olarak adlandırılır.

## RPC çalışma prensibi

![](images/8.4.rpc.png?raw=true)

Şekil 8.8 RPC çalışma prensibi

Normal şartlarda, istemciden sunucuya yapılan bir RPC çağrısı şu on adımdan oluşur:

- 1. İstemci handle'ını çağırın, argümanları transfer edin.
- 2. Ağ mesajlarını göndermek için yerel sistem kernel'ini çağırın.
- 3. Mesajları uzak host'lara gönderin.
- 4. Sunucu handle'ı ve argümanları alır.
- 5. Uzak süreçleri çalıştırın.
- 6. Çalıştırma sonucunu ilgili handle'a döndürün.
- 7. Sunucu handle'ı uzak sistem kernel'ini çağırır.
- 8. Mesajlar yerel sistem kernel'ine geri gönderilir.
- 9. İstemci handle'ı sistem kernel'inden mesajları alır.
- 10. İstemci, ilgili handle'dan sonuçları alır.

## Go RPC

Go, standart kütüphanesinde RPC için resmi destek sunar; bu destek TCP, HTTP ve JSON RPC olmak üzere üç seviyededir. Go RPC'nin diğer geleneksel RPC sistemlerine benzemediğine dikkat edin. İçeriği Gob ile kodladığı için hem istemci hem de sunucu tarafında Go uygulamaları kullanmanızı gerektirir.

Go RPC'nin fonksiyonları, uzaktan erişim için aşağıdaki kurallara uymalıdır; aksi hâlde ilgili çağrılar yok sayılır.

- Fonksiyonlar dışa açık olmalıdır (büyük harfle başlamalı).
- Fonksiyonların, dışa açık türlerde iki argümanı olmalıdır.
- İlk argüman istemciden gelen veriyi almak içindir, ikincisi ise pointer olmalıdır ve istemciye yanıt vermek içindir.
- Fonksiyonların `error` türünde bir dönüş değeri olmalıdır.

Örneğin:

	func (t *T) MethodName(argType T1, replyType *T2) error

Burada T, T1 ve T2 `package/gob` paketi tarafından kodlanabilir olmalıdır.

Herhangi bir RPC, veri transferi için bir ağ üzerinden geçmek zorundadır. Go RPC hem HTTP hem de TCP kullanabilir. HTTP kullanmanın faydası, `net/http` paketinden bazı fonksiyonları yeniden kullanabilmenizdir.

### HTTP RPC 

HTTP sunucu tarafı kodu:

	package main

	import (
		"errors"
		"fmt"
		"net/http"
		"net/rpc"
	)

	type Args struct {
		A, B int
	}

	type Quotient struct {
		Quo, Rem int
	}

	type Arith int

	func (t *Arith) Multiply(args *Args, reply *int) error {
		*reply = args.A * args.B
		return nil
	}

	func (t *Arith) Divide(args *Args, quo *Quotient) error {
		if args.B == 0 {
			return errors.New("divide by zero")
		}
		quo.Quo = args.A / args.B
		quo.Rem = args.A % args.B
		return nil
	}

	func main() {

		arith := new(Arith)
		rpc.Register(arith)
		rpc.HandleHTTP()

		err := http.ListenAndServe(":1234", nil)
		if err != nil {
			fmt.Println(err.Error())
		}
	}

Arith'in bir RPC servisini kaydettik, ardından bu servisi `rpc.HandleHTTP` ile HTTP üzerinde kaydettik. Bundan sonra, veriyi HTTP üzerinden transfer edebiliyoruz.

İstemci tarafı kodu:

	package main

	import (
		"fmt"
		"log"
		"net/rpc"
		"os"
	)

	type Args struct {
		A, B int
	}

	type Quotient struct {
		Quo, Rem int
	}


	func main() {
		if len(os.Args) != 2 {
			fmt.Println("Usage: ", os.Args[0], "server")
			os.Exit(1)
		}
		serverAddress := os.Args[1]

		client, err := rpc.DialHTTP("tcp", serverAddress+":1234")
		if err != nil {
			log.Fatal("dialing:", err)
		}
		// Synchronous call
		args := Args{17, 8}
		var reply int
		err = client.Call("Arith.Multiply", args, &reply)
		if err != nil {
			log.Fatal("arith error:", err)
		}
		fmt.Printf("Arith: %d*%d=%d\n", args.A, args.B, reply)

		var quot Quotient
		err = client.Call("Arith.Divide", args, &quot)
		if err != nil {
			log.Fatal("arith error:", err)
		}
		fmt.Printf("Arith: %d/%d=%d remainder %d\n", args.A, args.B, quot.Quo, quot.Rem)

	}

İstemci ve sunucu tarafı kodunu ayrı ayrı derleyip sonra sunucuyu ve istemciyi başlatıyoruz. Bazı veriler girdiğinizde aşağıdakine benzer bir çıktı elde edersiniz.

	$ ./http_c localhost
	Arith: 17*8=136
	Arith: 17/8=2 remainder 1

Gördüğünüz gibi, dönüş türü için bir struct tanımladık. Bunu sunucu tarafında fonksiyon argümanının türü olarak, istemci tarafındaki `client.Call` çağrısında ise ikinci ve üçüncü argümanların türü olarak kullanıyoruz. Bu çağrı çok önemlidir. Üç argümanı vardır; birincisi çağrılacak fonksiyonun adı, ikincisi geçirmek istediğiniz argüman, sonuncusu ise dönüş değeridir (pointer türünde). Buraya kadar Go'da RPC uygulamanın ne kadar kolay olduğunu gördük.

### TCP RPC

TCP tabanlı RPC'yi deneyelim; işte sunucu tarafı kodu:

	package main

	import (
		"errors"
		"fmt"
		"net"
		"net/rpc"
		"os"
	)

	type Args struct {
		A, B int
	}

	type Quotient struct {
		Quo, Rem int
	}

	type Arith int

	func (t *Arith) Multiply(args *Args, reply *int) error {
		*reply = args.A * args.B
		return nil
	}

	func (t *Arith) Divide(args *Args, quo *Quotient) error {
		if args.B == 0 {
			return errors.New("divide by zero")
		}
		quo.Quo = args.A / args.B
		quo.Rem = args.A % args.B
		return nil
	}

	func main() {

		arith := new(Arith)
		rpc.Register(arith)

		tcpAddr, err := net.ResolveTCPAddr("tcp", ":1234")
		checkError(err)

		listener, err := net.ListenTCP("tcp", tcpAddr)
		checkError(err)

		for {
			conn, err := listener.Accept()
			if err != nil {
				continue
			}
			rpc.ServeConn(conn)
		}

	}

	func checkError(err error) {
		if err != nil {
			fmt.Println("Fatal error ", err.Error())
			os.Exit(1)
		}
	}

HTTP RPC ile TCP RPC arasındaki fark, TCP RPC kullanırsak bağlantıları kendimizin kontrol etmek zorunda olması, ardından bağlantıları işlenmesi için RPC'ye iletmemiz gerektiğidir.

Tahmin edebileceğiniz gibi, bu bloklayan (blocking) bir örüntüdür. Bu uygulamayı daha ileri bir deney olarak genişletmek için goroutine'ler kullanmakta özgürsünüz.

İstemci tarafı kodu:

	package main

	import (
		"fmt"
		"log"
		"net/rpc"
		"os"
	)

	type Args struct {
		A, B int
	}

	type Quotient struct {
		Quo, Rem int
	}

	func main() {
		if len(os.Args) != 2 {
			fmt.Println("Usage: ", os.Args[0], "server:port")
			os.Exit(1)
		}
		service := os.Args[1]

		client, err := rpc.Dial("tcp", service)
		if err != nil {
			log.Fatal("dialing:", err)
		}
		// Synchronous call
		args := Args{17, 8}
		var reply int
		err = client.Call("Arith.Multiply", args, &reply)
		if err != nil {
			log.Fatal("arith error:", err)
		}
		fmt.Printf("Arith: %d*%d=%d\n", args.A, args.B, reply)

		var quot Quotient
		err = client.Call("Arith.Divide", args, &quot)
		if err != nil {
			log.Fatal("arith error:", err)
		}
		fmt.Printf("Arith: %d/%d=%d remainder %d\n", args.A, args.B, quot.Quo, quot.Rem)

	}

İstemci tarafı kodundaki tek fark, HTTP istemcilerinin DialHTTP kullanması, TCP istemcilerinin ise Dial(TCP) kullanmasıdır.

### JSON RPC

JSON RPC, veriyi gob yerine JSON'a kodlar. Sunucuda bir Go JSON RPC örneğine bakalım:

	package main

	import (
		"errors"
		"fmt"
		"net"
		"net/rpc"
		"net/rpc/jsonrpc"
		"os"
	)

	type Args struct {
		A, B int
	}

	type Quotient struct {
		Quo, Rem int
	}

	type Arith int

	func (t *Arith) Multiply(args *Args, reply *int) error {
		*reply = args.A * args.B
		return nil
	}

	func (t *Arith) Divide(args *Args, quo *Quotient) error {
		if args.B == 0 {
			return errors.New("divide by zero")
		}
		quo.Quo = args.A / args.B
		quo.Rem = args.A % args.B
		return nil
	}

	func main() {

		arith := new(Arith)
		rpc.Register(arith)

		tcpAddr, err := net.ResolveTCPAddr("tcp", ":1234")
		checkError(err)

		listener, err := net.ListenTCP("tcp", tcpAddr)
		checkError(err)

		for {
			conn, err := listener.Accept()
			if err != nil {
				continue
			}
			jsonrpc.ServeConn(conn)
		}

	}

	func checkError(err error) {
		if err != nil {
			fmt.Println("Fatal error ", err.Error())
			os.Exit(1)
		}
	}

JSON RPC, TCP tabanlıdır ve henüz HTTP'yi desteklemez.

## Özet

Go, HTTP, TCP ve JSON RPC uygulamaları için iyi bir destek sunar; bu da dağıtık web uygulamaları geliştirmemizi kolaylaştırır. Ancak Go'nun SOAP RPC için yerleşik desteği olmaması ne yazık ki üzücüdür, gerçi bazı açık kaynaklı üçüncü parti paketler bu desteği sunmaktadır.

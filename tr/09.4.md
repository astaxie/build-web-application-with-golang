# 9.4 SQL enjeksiyonu

## SQL enjeksiyonu nedir

SQL enjeksiyon saldırıları (adından da anlaşılacağı gibi) pek çok script enjeksiyon saldırısı türünden biridir. Web geliştirmede bunlar en yaygın güvenlik açığı biçimidir. Saldırganlar bunu kullanarak veritabanlarından hassas bilgiler elde edebilir; bir saldırı kapsamında veritabanına kullanıcı eklemek, özel dosyaları dışa aktarmak, hatta kendi kötü niyetli amaçları için sistemde en üst düzey yetkileri ele geçirmek de söz konusu olabilir.

SQL enjeksiyonu, web uygulamaları kullanıcı girdisini etkin biçimde filtrelemediğinde ortaya çıkar; bu durum saldırganların sunucuya kötü niyetli SQL sorgu kodu göndermesi için kapıyı ardına kadar açık bırakır. Uygulamalar genellikle enjekte edilen kodu saldırganın girdisinin bir parçası olarak alır ve bu, özgün sorgunun mantığını bir şekilde değiştirir. Uygulama sorguyu çalıştırmaya çalıştığında, saldırganın kötü niyetli kodu bunun yerine çalıştırılmış olur.

## SQL enjeksiyonu örnekleri

Birçok web geliştiricisi SQL sorgularının nasıl kurcalanabileceğinin farkında değildir ve bunların güvenilir komutlar olduğu yanılgısına düşebilir. Herkesin bildiği gibi, SQL sorguları erişim kontrollerini atlatabilir, böylece standart kimlik doğrulama ve yetkilendirme kontrollerini geçersiz kılabilir. Dahası, host sistemi düzeyindeki komutlar aracılığıyla SQL sorguları çalıştırmak da mümkündür.

SQL enjeksiyonu sürecini ayrıntılı şekilde açıklamak için birkaç gerçek örneğe göz atalım.

Aşağıdaki basit giriş formunu ele alalım:

	<form action="/login" method="POST">
	<p>Kullanıcı Adı: <input type="text" name="username" /></p>
	<p>Parola: <input type="password" name="password" /></p>
	<p><input type="submit" value="Giriş" /></p>
	</form>

Form işleme kodumuz şöyle görünebilir:

	username := r.Form.Get("username")
	password := r.Form.Get("password")
	sql := "SELECT * FROM user WHERE username='" + username + "' AND password='" + password + "'"

Kullanıcı, kullanıcı adı veya parola olarak şunu girerse:

	myuser' or 'foo' = 'foo' --

O zaman SQL'imiz şu hale gelir:

	SELECT * FROM user WHERE username='myuser' or 'foo' = 'foo' --'' AND password='xxx'

SQL'de `--` işaretinden sonraki her şey yorumdur. Böylece, saldırganın yukarıda yaptığı gibi `--` eklemesi sorguyu ölümcül biçimde değiştirir ve saldırganın geçerli bir parola olmadan bir kullanıcı olarak başarıyla giriş yapmasına olanak tanır.

MSSQL SQL enjeksiyonları için çok daha tehlikeli açıklar mevcuttur ve bazıları sistem komutları bile çalıştırabilir. Aşağıdaki örnekler, bazı MSSQL veritabanı sürümlerinde SQL enjeksiyonlarının ne kadar korkunç olabileceğini gösterecek.

	sql := "SELECT * FROM products WHERE name LIKE '%" + prod + "%'"
	Db.Exec(sql)

Bir saldırgan "prod" değişkeni olarak `a%' exec master..xp_cmdshell 'net user test testpass /ADD' --` gönderirse, sql şu hale gelir:

	sql := "SELECT * FROM products WHERE name LIKE '%a%' exec master..xp_cmdshell 'net user test testpass /ADD'--%'"

MSSQL Sunucusu, kullanıcının sağladığı "prod" değişkenindeki komutlar dahil SQL ifadesini çalıştırır ve bu da sisteme yeni kullanıcılar ekler. Bu program olduğu gibi çalıştırılırsa ve MSSQLSERVER servisi yeterli yetkilere sahipse, bir saldırgan bu makineye erişmek için bir sistem hesabı kaydedebilir.

> Yukarıdaki örnekler belirli bir veritabanı sistemine bağlı olsa da, bu diğer veritabanı sistemlerinin benzer tür saldırılara maruz kalamayacağı anlamına gelmez. SQL enjeksiyon saldırılarının arkasındaki ilkeler aynı kalır, ancak uygulanma yöntemi değişebilir.

## SQL enjeksiyonu nasıl önlenir

Bir saldırganın SQL enjeksiyon saldırısı gerçekleştirebilmesi için hedef veritabanının yapısı hakkında bilgi sahibi olması gerektiğini düşünüyor olabilirsiniz. Bu doğru olsa da, bir saldırganın bu bilgiyi bulamayacağını garanti etmek zordur ve bu bilgiyi ele geçirdiğinde veritabanı tehlikeye girebilir. Veritabanına erişmek için bir forum uygulaması gibi açık kaynak yazılım kullanıyorsanız, saldırganlar ilgili kodu kolayca elde edebilir. Kötü tasarlanmış kodla açıkça güvenlik riskleri daha da büyüktür. Discuz, phpwind ve phpcms, SQL enjeksiyon saldırılarına karşı savunmasız kalmış popüler açık kaynak programlara birer örnektir.

Bu saldırılar, güvenlik önlemlerine öncelik verilmeyen sistemlerde meydana gelir. Daha önce de söyledik, yine söyleyelim: hiçbir girdiye, özellikle kullanıcı verisine güvenmeyin. Buna seçim kutularından, gizli girdi alanlarından veya çerezlerden gelen veriler de dahildir. Yukarıdaki ilk örneğimizin gösterdiği gibi, görünüşte normal sorgular bile felakete yol açabilir.

SQL enjeksiyon saldırıları yıkıcı olabilir -peki bunlara karşı savunmaya nasıl başlayabiliriz? Aşağıdaki öneriler, SQL enjeksiyonunu önlemek için iyi bir başlangıç noktasıdır:

1. Veritabanı işlemleri için izinleri sıkı biçimde sınırlandırın, böylece kullanıcılar yalnızca işlerini yapmak için gereken minimum izin kümesine sahip olur ve bu da veritabanı enjeksiyon saldırısı riskini en aza indirir.
2. Girdi verisinin beklenen veri biçiminde olduğunu kontrol edin ve gönderilebilecek değişken türlerini sıkı biçimde sınırlandırın. Bu, regexp eşleştirmesini veya dizgileri arındırma ve değerlendirme için diğer temel türlere dönüştürmek üzere strconv paketini kullanmayı içerebilir.
3. Özel karakter çiftlerini ( '"\&*; vb. ) veritabanına kaydetmeden önce dönüştürün veya escape edin. Go'nun `text/template` paketinde, escape edilmiş HTML döndürmek için kullanılabilecek bir `HTMLEscapeString` fonksiyonu bulunur.
4. Veritabanınızın parametreli sorgu arayüzünü kullanın. Parametreli ifadeler, gömülü SQL ifadelerinde kullanıcı girdi değişkenlerini birleştirmek yerine parametreler kullanır; başka bir deyişle, SQL ifadelerini doğrudan birbirine eklemezler. Örneğin, Go'nun `database/sql` paketindeki `Prepare` fonksiyonunu kullanarak, daha sonra `Query` veya `Exec(query string, args... interface {})` ile çalıştırılmak üzere hazırlanmış ifadeler oluşturabiliriz.
5. Uygulamanızı yayınlamadan önce, SQL enjeksiyon açıklarını tespit etmek için profesyonel araçlarla kapsamlı biçimde test edin ve varsa bunları onarın. sqlmap, SQLninja gibi, tam olarak bunu yapan pek çok çevrimiçi açık kaynak araç bulunmaktadır.
6. Herkese açık web sayfalarında SQL hata bilgisini yazdırmaktan kaçının. Saldırganlar SQL enjeksiyon saldırısı gerçekleştirmek için bu hata mesajlarını kullanabilir. Bu tür hatalara örnek olarak tür hataları, alan eşleşmeme hataları veya SQL ifadeleri içeren herhangi bir hata verilebilir.

## Özet

Yukarıdaki örnekler aracılığıyla, SQL enjeksiyonunun gerçekten var olan ve çok tehlikeli bir web güvenlik açığı olduğunu öğrendik. Web uygulaması yazarken, her küçük ayrıntıya dikkat etmeli ve güvenlik konularını büyük bir özenle ele almalıyız. Bunu yapmak, daha iyi ve daha güvenli web uygulamalarına yol açacak ve nihayetinde uygulamanızın başarılı olup olmayacağını belirleyen etken olabilecektir.

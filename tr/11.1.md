# 11.1 Hata yakalama

Go'nun temel tasarım ilkeleri şu fikirlere dayanır: sade, açık ve öz bir söz dizimi (C'ye benzer) ve gizli ya da beklenmedik hiçbir şey içermeyen, açıkça anlaşılır ifadeler. Go'nun hata yakalama şeması, uygulanış biçimiyle bu ilkelerin tamamını yansıtır. C dilini biliyorsanız, bir hatanın oluştuğunu belirtmek için -1 veya NULL değerlerinin döndürülmesinin yaygın olduğunu bilirsiniz. Ancak C'nin API'sine aşina olmayan kullanıcılar bu dönüş değerlerinin tam olarak ne anlama geldiğini bilemez. C'de, `0` değerinin başarıyı mı yoksa başarısızlığı mı belirttiği açık değildir. Öte yandan Go, yalnızca hataları ifade etmek amacıyla `error` adında bir tür açıkça tanımlar. Bir fonksiyon döndüğünde, işlemin başarılı olup olmadığını anlamak için hata değişkeninin `nil` olup olmadığına bakarız. Örneğin `os.Open` fonksiyonu başarısız olursa, nil olmayan bir hata değişkeni döndürür.  

    func Open(name string) (file * File, err error)

İşte `os.Open` içindeki bir hatayı nasıl ele alacağımıza dair bir örnek. Önce bir dosya açmayı deneriz. Fonksiyon döndüğünde, hata dönüş değerini nil ile karşılaştırarak başarılı olup olmadığına bakarız; değer nil değilse `log.Fatal` çağrılarak bir hata mesajı çıktılanır:

    f, err := os.Open("filename.ext")
    if err != nil {
      log.Fatal(err)
    }

`os.Open` fonksiyonuna benzer şekilde, Go'nun standart paketlerindeki fonksiyonların tamamı hata yakalamayı kolaylaştırmak için hata değişkenleri döndürür. Bu bölümde hata türlerinin tasarımını ayrıntılı olarak ele alacak ve web uygulamalarında hataların doğru şekilde nasıl yakalanacağını tartışacağız. 

## Hata türü

`error`, aşağıdaki tanıma sahip bir interface türüdür:

    type error interface {
		Error() string
	}

`error`, yerleşik bir interface türüdür. Tanımını aşağıdaki builtin paketinde bulabiliriz. Ayrıca birçok iç paket, `error` interface'ini uygulayan `errorString` adlı private bir yapıda `error` türünü kullanır:

    // errorString, error'ın basit bir uygulamasıdır.
	type errorString struct {
		s string
	}

	func (e *errorString) Error() string {
		return e.s
	}

error interface'ini karşılayan bir nesne elde etmek için sıradan bir string'i `errors.New` aracılığıyla bir `errorString`'e dönüştürebilirsiniz. İç uygulaması şu şekildedir:

    // New, verilen metni biçimlendiren bir hata döndürür.
	func New(text string) error {
		return &errorString{text}
	}

Aşağıdaki örnek `errors.New`'in nasıl kullanılacağını gösterir:

    func Sqrt(f float64) (float64, error) {
		if f < 0 {
			return 0, errors.New("math: square root of negative number")
		}
		// uygulama
	}

Aşağıdaki örnekte, `Sqrt` fonksiyonumuza negatif bir sayı veriyoruz. `err` değişkenini kontrol ederek, basit bir nil karşılaştırmasıyla hata nesnesinin nil olup olmadığına bakıyoruz. Karşılaştırmanın sonucu true olduğundan, bir hata çıktılamak için `fmt.Println` çağrılır (`fmt` paketi, hata çağrılarıyla uğraşırken error method'unu çağırır). 

    f, err := Sqrt(-1)
    if err != nil {
        fmt.Println(err)
    }	

## Özel hatalar

Yukarıdaki açıklamadan, Go'da bir Error'ın bir interface olduğunu biliyoruz. Bu interface'i uygulayan bir struct tanımlayarak, kendi hata tanımlarımızı gerçekleştirebiliriz. İşte JSON paketinden bir örnek:

    type SyntaxError struct {
        msg string // hata açıklaması
        Offset int64 // hatanın oluştuğu yer
    }

    func (e * SyntaxError) Error() string {return e.msg}

Söz dizimi hataları oluştuğunda hatanın `Offset` alanı çalışma zamanında yazdırılmaz; ancak bir type assertion kullanarak istenen hata mesajını yazdırabilirsiniz:

    if err := dec.Decode(&val); err != nil {
		if serr, ok := err.(*json.SyntaxError); ok {
			line, col := findLine(f, serr.Offset)
			return fmt.Errorf("%s:%d:%d: %v", f.Name(), line, col, err)
		}
		return err
	}

Şunu belirtmek gerekir: fonksiyon özel bir hata döndürürken, dönüş değerinin türü özel hata türü yerine önerilen error türü olarak ayarlanmalıdır. Özel hata türlerinden değişkenleri önceden bildirmemeye dikkat edin. Örneğin:

    func Decode() *SyntaxError {
        // hata: bu, çağıranın err != nil karşılaştırmasının her zaman true olmasına yol açabilir.
        var err * SyntaxError // hata değişkenini önceden bildir
        if an error condition {
            err = &SyntaxError{}
        }
        return err // hata: err her zaman non-nil'e eşit olur, bu da çağıranın err != nil karşılaştırmasının her zaman true olmasına neden olur
    }

Derinlemesine bir açıklama için bkz. http://golang.org/doc/faq#nil_error 

Yukarıdaki örnek basit bir özel Error türünün nasıl uygulanacağını gösterir. Peki ya daha gelişmiş bir hata yakalamaya ihtiyacımız olursa? Bu durumda `net` paketinin yaklaşımına başvurmamız gerekir:

    package net

	type Error interface {
	    error
	    Timeout() bool   // Hata bir zaman aşımı mı?
	    Temporary() bool // Hata geçici mi?
	}


Type assertion kullanarak, aşağıdaki örnekte gösterildiği gibi hatamızın net.Error türünde olup olmadığını kontrol edebiliriz. Bu, hata yakalamamızı daha ince ayarlı hale getirmemizi sağlar -ağda geçici bir hata oluşursa, 1 saniye bekler, ardından işlemi yeniden dener. 

    if nerr, ok := err.(net.Error); ok && nerr.Temporary() {
		time.Sleep(1e9)
		continue
	}
	if err != nil {
		log.Fatal(err)
	}

## Hata yakalama

Go, hataları ele alma ve fonksiyonların dönüş değerlerini kontrol etme konusunda C benzeri bir yol izler; bu, diğer büyük dillerin çoğunun yaptığından farklıdır. Bu, kodu daha açık ve öngörülebilir kılar, ama aynı zamanda daha ayrıntılı hale getirir. Hata yakalama kodumuzdaki tekrarı azaltmak için, benzer hata yakalama davranışını uygulamamızı sağlayan soyut hata yakalama fonksiyonları kullanabiliriz: 

    func init() {
		http.HandleFunc("/view", viewRecord)
	}

	func viewRecord(w http.ResponseWriter, r *http.Request) {
		c := appengine.NewContext(r)
		key := datastore.NewKey(c, "Record", r.FormValue("id"), 0, nil)
		record := new(Record)
		if err := datastore.Get(c, key, record); err != nil {
			http.Error(w, err.Error(), 500)
			return
		}
		if err := viewTemplate.Execute(w, record); err != nil {
			http.Error(w, err.Error(), 500)
		}
	}

Yukarıdaki örnek, veri erişiminin ve şablon çağrısının bir hatayı nasıl tespit ettiğini gösterir. Bir hata oluştuğunda, birleşik handler http.Error çağrılır, istemciye 500 hata kodu döner ve ilgili hata verisini görüntüler. Ancak giderek daha fazla HandleFunc çağrısı yapıldıkça, hata yakalama mantık kodu da artacaktır. Kodu azaltmak için yönlendiriciyi özelleştirebiliriz (ayrıntı için HTTP'nin üçüncü bölümüne bakın).

    type appHandler func(http.ResponseWriter, *http.Request) error

	func (fn appHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
		if err := fn(w, r); err != nil {
			http.Error(w, err.Error(), 500)
		}
	}

Yukarıda özel bir yönlendirici tanımladık. Ardından handler'ımızı her zamanki gibi kaydedebiliriz:

    func init() {
		http.Handle("/view", appHandler(viewRecord))
	}

`/view` handler'ı artık aşağıdaki kodla ele alınabilir; orijinal uygulamamızdan çok daha basit değil mi? 

    func viewRecord(w http.ResponseWriter, r *http.Request) error {
		c := appengine.NewContext(r)
		key := datastore.NewKey(c, "Record", r.FormValue("id"), 0, nil)
		record := new(Record)
		if err := datastore.Get(c, key, record); err != nil {
			return err
		}
		return viewTemplate.Execute(w, record)
	}

Yukarıdaki hata handler'ı örneği, herhangi bir hata oluştuğunda kullanıcılara 500 Internal Error kodunu döndürür ve ilgili hata kodunu da yazdırır. Aslında, döndürülen hatanın türünü özelleştirerek, hata ayıklama için yararlı bilgiler içeren, geliştirici dostu bir hata mesajı çıktılayabiliriz:  

    type appError struct {
		Error   error
		Message string
		Code    int
	}

Özel yönlendiricimiz buna göre değiştirilebilir:

    type appHandler func(http.ResponseWriter, *http.Request) *appError

	func (fn appHandler) ServeHTTP(w http.ResponseWriter, r *http.Request) {
		if e := fn(w, r); e != nil { // e bir *appError'dur, os.Error değil.
			c := appengine.NewContext(r)
			c.Errorf("%v", e.Error)
			http.Error(w, e.Message, e.Code)
		}
	}

Özel hatamızı değiştirmeyi tamamladıktan sonra, mantığımız şu şekilde değiştirilebilir:

    func viewRecord(w http.ResponseWriter, r *http.Request) *appError {
		c := appengine.NewContext(r)
		key := datastore.NewKey(c, "Record", r.FormValue("id"), 0, nil)
		record := new(Record)
		if err := datastore.Get(c, key, record); err != nil {
			return &appError{err, "Kayıt bulunamadı", 404}
		}
		if err := viewTemplate.Execute(w, record); err != nil {
			return &appError{err, "Kayıt görüntülenemiyor", 500}
		}
		return nil
	}

Yukarıda gösterildiği gibi, view'larımızda duruma göre farklı hata kodları ve hata mesajları döndürebiliriz. Bu kod sürümü önceki sürümle benzer şekilde işlese de, daha açıktır ve hata mesajı bildirimleri daha anlaşılırdır. Bütün bu etkenler, karmaşıklık arttıkça uygulamanızın daha ölçeklenebilir olmasına yardımcı olabilir.     

## Özet

Hata toleransı, herhangi bir programlama dilinin çok önemli bir yönüdür. Go'da bu, hata yakalama yoluyla sağlanır. `Error` yalnızca tek bir interface olsa da, uygulanış biçiminde birçok varyasyona sahip olabilir ve ihtiyaçlarımıza göre duruma özel olarak özelleştirebiliriz. Bu çeşitli hata yakalama kavramlarını tanıtarak, kendi web uygulamalarınızda daha iyi hata yakalama şemaları uygulama konusunda size bir fikir vermiş olmayı umuyoruz.

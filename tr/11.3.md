# 11.3 Test durumları yazmak

Geliştirme sürecinde çok önemli bir adım, kodumuzun kalitesini ve bütünlüğünü güvence altına almak için onu test etmektir. Her fonksiyonun beklenen sonucu döndürdüğünden ve kodumuzun en iyi performansla çalıştığından emin olmamız gerekir. Birim testlerinin (unit test) odak noktasının, programların tasarımındaki veya uygulanmasındaki mantık hatalarını bulmak olduğunu zaten biliyoruz. Bu testler, kodda oluşan sorunları işin içinden çıkılmaz hale gelmeden önce erkenden tespit edip ortaya çıkarmak ve böylece daha kolay düzeltebilmemiz için kullanılır. Ayrıca performans testlerinin, kodumuzu yük altında kararlı hale getirmek ve yüksek düzeyde eşzamanlılığı sürdürebilmesini sağlamak amacıyla optimize etmek için yapıldığını da biliyoruz. Bu bölümde, Go'da birim ve performans testlerinin nasıl uygulandığına dair sıkça sorulan bazı sorulara göz atacağız.     

Go dili, `testing` adında hafif bir test çatısıyla birlikte gelir ve birim ve performans testlerini çalıştırmak için `go test` komutunu kullanabiliriz. Go'nun `testing` çatısı, diğer dillerdeki test çatılarına benzer şekilde çalışır. Bunlarla birim testleri, kıyaslama (benchmarking), stres testleri ve benzerlerini içerebilecek her türlü test paketini geliştirebilirsiniz. Go'da testleri adım adım öğrenelim.       

## Test durumları nasıl yazılır

`go test` komutu yalnızca ilgili tüm dosyaları içeren bir dizinde çalıştırılabildiğinden, tüm kodumuzun ve test kodumuzun aynı dizinde olması için `gotest` adında yeni bir proje dizini oluşturacağız.

Şimdi gotest adlı dizinde gotest.go ve gotest_test.go adında iki dosya oluşturalım.

1. Gotest.go: Bu dosya paket adımızı bildirir ve bölme işlemi yapan bir fonksiyon içerir:

	<pre>package gotest
	
	import (
		"errors"
	)
	
	func Division(a, b float64) (float64, error) {
		if b == 0 {
			return 0, errors.New("Bölen 0 olamaz")
		}
		return a / b, nil
	}</pre>

2. Gotest_test.go: Bu bizim birim test dosyamız. Test dosyaları için aşağıdaki ilkeleri aklınızda tutun:

- Dosya adları, `go test` komutunun ilgili kodu bulup çalıştırabilmesi için `_test.go` ile bitmelidir
- `testing` paketini import etmeniz gerekir
- Tüm test durumu fonksiyonları `Test` ile başlar
- Test durumları kaynak kod sırasını takip eder
- `TestXxx()` biçimindeki test fonksiyonları bir `testing.T` argümanı alır; bu türü hataları kaydetmek veya test durumunu almak için kullanabiliriz
- `func TestXxx(t * testing.T)` biçimindeki fonksiyonlarda, `Xxx` kısmı herhangi bir alfanümerik kombinasyon olabilir, ancak ilk harf küçük harf [a-z] olamaz. Örneğin, `Testintdiv` geçersiz bir fonksiyon adı olurdu.
- Test fonksiyonlarımızda `testing.T`'nin `Error`, `Errorf`, `FailNow`, `Fatal` veya `FatalIf` methodlarından birini çağırarak testi başarısız kılabiliriz. Ayrıca, bilgiyi hata loguna kaydetmek için `testing.T`'nin `Log` methodunu çağırabiliriz. 

İşte test kodumuz:

	package gotest

	import (
		"testing"
	)

	func Test_Division_1(t *testing.T) {
		// fonksiyon üzerinde bir birim testi dene
		if i, e := Division(6, 2); i != 3 || e != nil { 
			// Beklendiği gibi değilse, test başarısız olmuştur 
			t.Error("bölme fonksiyonu testleri geçmiyor ") 
		} else {
			// beklenen bilgiyi kaydet
			t.Log("ilk test geçti ") 
		}
	}

	func Test_Division_2(t *testing.T) {
		t.Error("sadece geçmiyor")
	}


Proje dizininde `go test` çalıştırıldığında aşağıdaki bilgiler görüntülenecektir:

	--- FAIL: Test_Division_2 (0.00 seconds)
	gotest_test.go: 16: geçmedi
	FAIL
	exit status 1
	FAIL gotest 0.013s
	
Bu sonuçtan, `t.Error` kullanarak bir çıkmaz sokak yazdığımız için ikinci test fonksiyonunun geçmediğini görebiliriz. Peki ilk test fonksiyonumuzun performansı ne durumda? Varsayılan olarak, `go test` çalıştırıldığında test sonuçları görüntülenmez. Aşağıdaki çıktıyı görüntülemek için `-v` ayrıntı (verbose) argümanını `go test -v` şeklinde eklememiz gerekir:

	=== RUN Test_Division_1
	--- PASS: Test_Division_1 (0.00 seconds)
	gotest_test.go: 11: ilk test geçti
	=== RUN Test_Division_2
	--- FAIL: Test_Division_2 (0.00 seconds)
	gotest_test.go: 16: geçmedi
	FAIL
	exit status 1
	FAIL gotest 0.012s
	
Yukarıdaki çıktı, testimizin sonuçlarını ayrıntılı biçimde gösteriyor. 1. test fonksiyonu `Test_Division_1`'in geçtiğini, 2. test fonksiyonu `Test_Division_2`'nin ise başarısız olduğunu görüyoruz; sonuç olarak test paketimizin geçmediği ortaya çıkıyor. Şimdi, 2. test fonksiyonunu aşağıdaki kodla değiştirelim:

	func Test_Division_2(t *testing.T) {
		// fonksiyon üzerinde bir birim testi dene
		if _, e := Division(6, 0); e == nil { 
			// Beklendiği gibi değilse, hata 
			t.Error("Division beklendiği gibi çalışmadı.") 
		} else {
			// kaydetmek istediğiniz bazı bilgileri kaydedin
			t.Log("bir test geçti.", e) 
		}
	}

`go test -v` komutunu tekrar çalıştırıyoruz. Artık aşağıdaki bilgiler görüntülenmeli -test paketi geçti-:

	=== RUN Test_Division_1
	--- PASS: Test_Division_1 (0.00 seconds)
	gotest_test.go: 11: ilk test geçti
	=== RUN Test_Division_2
	--- PASS: Test_Division_2 (0.00 seconds)
	gotest_test.go: 20: bir test geçti. bölen 0 olamaz
	PASS
	ok gotest 0.013s

## Stres testleri nasıl yazılır

Stres testi, fonksiyon performansını tespit etmek için kullanılır ve birim testine bazı açılardan benzer (burada buna girmeyeceğiz), ancak aşağıdaki noktalara dikkat etmemiz gerekir:

- Stres testleri aşağıdaki biçimi izlemelidir; burada XXX herhangi bir alfanümerik kombinasyon olabilir ve ilk harfi küçük harf olamaz. 

	func BenchmarkXXX (b *testing.B){...}

- Varsayılan olarak, `Go test` fonksiyon stres testlerini çalıştırmaz. Stres testlerini çalıştırmak isterseniz, `-test.bench` bayrağını şu biçimde ayarlamanız gerekir: `-test.bench="test_name_regex"`. Örneğin, paketinizdeki tüm stres testlerini çalıştırmak için `go test -test.bench=".*"` komutunu çalıştırırsınız. 
- Stres testlerinizde, testlerin düzgün çalışabilmesi için döngü gövdelerinde testing.B.N kullanmayı unutmayın.
- Daha önce olduğu gibi, test dosyası adları `_test.go` ile bitmelidir

Şimdi webbench_test.go adında bir stres testi dosyası oluşturalım:

	package gotest

	import (
		"testing"
	)

	func Benchmark_Division(b *testing.B) {
		for i := 0; i < b.N; i++ { // döngü için b.N kullan
			Division(4, 5)
		}
	}

	func Benchmark_TimeConsumingFunction(b *testing.B) {
		b.StopTimer() // stres testi süre sayacını durdurmak için fonksiyonu çağır

		// Dosya verisi okuma, veritabanı bağlantıları gibi bazı ilklendirme
		// işlerini yapın, böylece kıyaslamalarımız fonksiyonun kendi
		// performansını yansıtsın

		b.StartTimer() // süreyi yeniden başlat
		for i := 0; i < b.N; i++ {
			Division(4, 5)
		}
	}



Ardından `go test -file webbench_test.go -test.bench =".*"` komutunu çalıştırırız, bu da aşağıdaki sonuçları verir:

	PASS
	Benchmark_Division 500000000 7.76 ns/ op
	Benchmark_TimeConsumingFunction 500000000 7.80 ns/ op
	ok gotest 9.364s

Yukarıdaki sonuçlar, herhangi bir `TestXXX` birim test fonksiyonumuzu çalıştırmadığımızı, bunun yerine yalnızca `BenchmarkXXX` testlerimizi çalıştırdığımızı gösteriyor (ki tam olarak beklendiği gibi). İlk `Benchmark_Division` testi, `Division()` fonksiyonumuzun 500 milyon kez çalıştırıldığını ve ortalama çalışma süresinin 7.76ns olduğunu gösteriyor. İkinci `Benchmark_TimeConsumingFunction` ise `TmeConsumingFunction`'ın 500 milyon kez çalıştırıldığını ve ortalama çalışma süresinin 7.80ns olduğunu gösteriyor. Son olarak, test paketimizin toplam çalışma süresini yazdırıyor.

## Özet

Go'da birim ve stres testleriyle olan bu kısa deneyimimizden, `testing` paketinin çok hafif olmasına rağmen kullanışlı araçlarla dolu olduğunu görebiliyoruz. Birim ve stres testleri yazmanın çok basit olabileceğini ve bunları çalıştırmanın Go'nun yerleşik `go test` komutuyla daha da kolay olabileceğini gördük. Kodumuzu her değiştirdiğimizde, regresyon testine başlamak için basitçe `go test` çalıştırabiliriz.

# 12.3 Yayınlama

Web uygulamamız sonunda üretime hazır hale geldiğinde, onu yayınlamak için hangi adımlar gereklidir? Go'da, programlarımızı derledikten sonra uygulamamızı içine alan çalıştırılabilir bir dosya oluşturulur. C ile yazılan programlar arka plan daemon süreçleri olarak mükemmel şekilde çalışabilir, ancak Go henüz daemon'lar için yerleşik destek sunmuyor. İyi haber şu ki, Go uygulamalarımızın yayınlanmasını yönetmemize yardımcı olacak üçüncü parti araçlar kullanabiliriz; bunların örnekleri arasında Supervisord, upstart ve daemontools sayılabilir. Bu bölümde sizi Supervisord süreç kontrol sisteminin bazı temelleriyle tanıştıracağız.

## Daemon'lar

Şu anda Go programları daemon süreçleri olarak çalıştırılamıyor (ek bilgi için GitHub'daki açık konuya [buradan](https://github.com/golang/go/issues/227) bakabilirsiniz). Go'da mevcut thread'leri fork etmek zordur, çünkü kullanılmış olan tüm thread'lerde tutarlı bir durumu garanti etmenin bir yolu yoktur.

Ancak, internette daemon uygulamalarına yönelik pek çok girişim görebiliriz; aşağıdaki iki yöntem gibi.

- MarGo, uygulamaları yayınlamak için `Command` kullanma fikrinin bir uygulamasıdır. Uygulamalarınızı gerçekten daemon haline getirmek istiyorsanız, aşağıdakine benzer bir kod kullanmanız önerilir:

<pre>
	d := flag.Bool("d", false, "Arka planda (daemon gibi) başlatılıp başlatılmayacağı")
	if *d {
		cmd := exec.Command(os.Args[0],
			"-close-fds",
			"-addr", *addr,
			"-call", *call,
		)
		serr, err := cmd.StderrPipe()
		if err != nil {
			log.Fatalln(err)
		}
		err = cmd.Start()
		if err != nil {
			log.Fatalln(err)
		}
		s, err := ioutil.ReadAll(serr)
		s = bytes.TrimSpace(s)
		if bytes.HasPrefix(s, []byte("addr: ")) {
			fmt.Println(string(s))
			cmd.Process.Release()
		} else {
			log.Printf("unexpected response from MarGo: `%s` error: `%v`\n", s, err)
			cmd.Process.Kill()
		}
	}
</pre>

- Başka bir çözüm de `syscall` kullanmaktır, ancak bu çözüm de kusursuz değildir:

```
	package main
	 
	import (
		"log"
		"os"
		"syscall"
	)
	 
	func daemon(nochdir, noclose int) int {
		var ret, ret2 uintptr
		var err uintptr
	 
		darwin := syscall.OS == "darwin"
	 
		// zaten bir daemon
		if syscall.Getppid() == 1 {
			return 0
		}
	 
		// üst süreci fork et
		ret, ret2, err = syscall.RawSyscall(syscall.SYS_FORK, 0, 0, 0)
		if err != 0 {
			return -1
		}
	 
		// başarısızlık
		if ret2 < 0 {
			os.Exit(-1)
		}
	 
		// darwin için istisnayı işle
		if darwin && ret2 == 1 {
			ret = 0
		}
	 
		// geçerli bir PID aldıysak, üst süreçten çıkarız
		if ret > 0 {
			os.Exit(0)
		}
	 
		/* Dosya mod maskesini değiştir */
		_ = syscall.Umask(0)
	 
		// alt süreç için yeni bir SID oluştur
		s_ret, s_errno := syscall.Setsid()
		if s_errno != 0 {
			log.Printf("Error: syscall.Setsid errno: %d", s_errno)
		}
		if s_ret < 0 {
			return -1
		}
	 
		if nochdir == 0 {
			os.Chdir("/")
		}
	 
		if noclose == 0 {
			f, e := os.OpenFile("/dev/null", os.O_RDWR, 0)
			if e == nil {
				fd := f.Fd()
				syscall.Dup2(fd, os.Stdin.Fd())
				syscall.Dup2(fd, os.Stdout.Fd())
				syscall.Dup2(fd, os.Stderr.Fd())
			}
		}
	 
		return 0
	}
```

Yukarıdaki iki çözüm Go'da daemon haline getirmeyi gerçekleştirse de, Go'da daemon'lar için resmi bir destek olmadığından bu yöntemlerden herhangi birini kullanmanızı yine de öneremem. Buna rağmen, ilk seçenek daha uygulanabilir olanıdır ve şu anda [skynet](https://github.com/skynetservices/skynet) gibi bazı tanınmış açık kaynak projeleri tarafından daemon'ları uygulamak için kullanılmaktadır.

## Supervisord

Yukarıda, Go'da daemon uygulamak için yaygın olarak kullanılan iki yönteme baktık, ancak her iki yöntem de resmi destekten yoksun. Bu nedenle, uygulama yayınlamayı yönetmek için üçüncü parti bir araç kullanmanız önerilir. Burada, Python'da uygulanmış ve süreç yönetimi için kapsamlı araçlar sunan Supervisord projesine bakacağız. Supervisord, Go uygulamalarınızı daemon haline getirmenize yardımcı olur; ayrıca uygulamalarınızı basit komutlarla başlatmanıza, kapatmanıza ve yeniden başlatmanıza ve daha pek çok başka işlemi yapmanıza olanak tanır. Buna ek olarak, Supervisord tarafından yönetilen süreçler çökmüş süreçleri otomatik olarak yeniden başlatabilir; böylece programların herhangi bir kesintiden kurtulabilmesi sağlanır.

> Bir kenar notu olarak, geçenlerde Supervisord kullanarak bir uygulama yayınlamaya çalışırken yaygın bir tuzağa düştüm. Supervisord kullanılarak yayınlanan tüm uygulamalar, Supervisord üst (parent) sürecinden doğar. Bir işletim sistemi dosya tanımlayıcısını değiştirdiğinizde, Supervisord'u tamamen yeniden başlatmayı unutmayın -sadece yönettiği uygulamayı yeniden başlatmak yeterli olmayacaktır. Supervisord ile ilk kez bir uygulama yayınladığımda, varsayılan dosya tanımlayıcısı alanını değiştirmiş, varsayılan sayıyı 1024'ten 100.000'e çıkarmış ve ardından uygulamamı yeniden başlatmıştım. Gerçekte, Supervisord uygulamamın tüm süreçlerini yönetmek için hâlâ yalnızca 1024 dosya tanımlayıcısı kullanmaya devam etti. Uygulamamı yayınladığımda, logger dosya tanımlayıcısı yetersizliği bildirmeye başladı! Bu hatayı bulup düzeltmek uzun bir süreç aldı, dikkatli olun!

### Supervisord kurulumu

Supervisord, `sudo easy_install supervisor` kullanılarak kolayca kurulabilir. Elbette, resmi web sitesinden doğrudan indirip, arşivden çıkarıp, klasöre girip `setup.py install` çalıştırarak manuel olarak kurma seçeneği de vardır.

- `easy_install` yolunu izleyecekseniz, öncelikle `setuptools`'u kurmanız gerekir

`http://pypi.python.org/pypi/setuptools#files` adresine gidin ve sisteminizin python sürümüne bağlı olarak uygun dosyayı indirin. Dizine girin ve `sh setuptoolsxxxx.egg` komutunu çalıştırın. Betik tamamlandığında, Supervisord'u kurmak için `easy_install` komutunu kullanabileceksiniz.

### Supervisord yapılandırması

Supervisord'un varsayılan yapılandırma dosyası yolu `/etc/supervisord.conf`'tur ve bir metin editörü kullanılarak değiştirilebilir. Aşağıda tipik bir yapılandırma dosyasının nasıl görünebileceği gösterilmektedir:

	;/etc/supervisord.conf
	[unix_http_server]
	file = /var/run/supervisord.sock
	chmod = 0777
	chown= root:root

	[inet_http_server]
	# Web yönetim arayüzü ayarları
	port=9001
	username = admin
	password = yourpassword

	[supervisorctl]
	; 'unix_http_server' içindeki ayarlarla eşleşmeli
	serverurl = unix:///var/run/supervisord.sock

	[supervisord]
	logfile=/var/log/supervisord/supervisord.log ; (ana log dosyası; varsayılan $CWD/supervisord.log)
	logfile_maxbytes=50MB       ; (rotasyondan önce ana log dosyasının max byte sayısı; varsayılan 50MB)
	logfile_backups=10          ; (ana log dosyası rotasyon yedeklerinin sayısı; varsayılan 10)
	loglevel=info               ; (log seviyesi; varsayılan info; diğerleri: debug,warn,trace)
	pidfile=/var/run/supervisord.pid ; (supervisord pid dosyası; varsayılan supervisord.pid)
	nodaemon=true              ; (true ise ön planda başlar; varsayılan false)
	minfds=1024                 ; (başlangıçta gereken min. dosya tanımlayıcısı sayısı; varsayılan 1024)
	minprocs=200                ; (min. gereken süreç tanımlayıcısı sayısı; varsayılan 200)
	user=root                 ; (varsayılan mevcut kullanıcıdır, root gerekiyorsa zorunludur)
	childlogdir=/var/log/supervisord/            ; ('AUTO' child log dizini, varsayılan $TEMP)

	[rpcinterface:supervisor]
	supervisor.rpcinterface_factory = supervisor.rpcinterface:make_main_rpcinterface
	; Tek bir sürecin yapılandırmasını yönetir, birden fazla program ekleyebilirsiniz
	[program: blogdemon]
	command =/data/blog/blogdemon
	autostart = true
	startsecs = 5
	user = root
	redirect_stderr = true
	stdout_logfile =/var/log/supervisord/blogdemon.log

### Supervisord yönetimi

Kurulum tamamlandıktan sonra, komut satırında size iki Supervisord komutu kullanılabilir hale gelir: `supervisor` ve `supervisorctl`. Komutlar şu şekildedir:

- `supervisord`: ilk başlatma, çalıştırma ve süreç yapılandırma yönetimi.
- `supervisorctl stop programxxx`: programxxx sürecini durdurur; burada programxxx, `supervisord.conf` dosyanızda yapılandırılmış bir değerdir. Örneğin, `[program: blogdemon]` gibi bir yapılandırmanız varsa, süreci sonlandırmak için `supervisorctl stop blogdemon` komutunu kullanırsınız.
- `supervisorctl start programxxx`: programxxx sürecini başlatır
- `supervisorctl restart programxxx`: programxxx sürecini yeniden başlatır
- `supervisorctl stop all`: tüm süreçleri durdurur; not: start, restart, stop en güncel yapılandırma dosyalarını yüklemez.
- `supervisorctl reload`: en güncel yapılandırma dosyasını yükler, çalıştırır ve tüm süreçleri yeni yapılandırmayla yönetir.

## Özet

Bu bölümde, Go'da daemon'ların nasıl uygulanacağını anlattık. Go'nun daemon'ları yerleşik olarak desteklemediğini ve onları yönetmemize yardımcı olması için üçüncü parti araçlar kullanmamız gerektiğini öğrendik. Bu araçlardan biri, Go programlarımızı kolayca yayınlayıp yönetmek için kullanabileceğimiz Supervisord süreç kontrol sistemidir.

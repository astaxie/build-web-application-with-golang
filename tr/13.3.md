# 13.3 Controller tasarlamak

Geleneksel MVC çatılarının çoğu, sonek tabanlı action eşlemesine dayanır. Günümüzde ise REST tarzı web mimarisi giderek daha popüler hale geliyor. URL'leri filtreleyerek veya yeniden yazarak REST tarzı URL'ler uygulamak mümkün olsa da, neden sıfırdan yeni bir REST tarzı MVC çatısı tasarlamayalım? Bu bölüm bu fikirden yola çıkarak, Controller tabanlı, REST tarzı bir MVC çatısını sıfırdan tasarlamaya ve uygulamaya odaklanır. Amacımız web uygulaması geliştirmeyi basitleştirmek, hatta belki de "Hello, world" servisi verebilecek tek satırlık bir kod yazabilmektir.

## Controller'ın rolü

MVC tasarım deseni, günümüzde web uygulamaları için en çok kullanılan çatı modelidir. Model, View ve Controller'ları birbirinden ayrı tutarak web uygulamalarımızı modüler, bakımı kolay, test edilebilir ve genişletilebilir hale getirebiliriz. Bir model, veriyi ve o veriyi yöneten erişilebilirlik kuralları, kalıcılık, doğrulama gibi iş mantığını kapsar. View'lar verinin temsili olarak görev yapar ve web uygulamalarında genellikle şablon olarak yaşarlar; bu şablonlar daha sonra HTML'e dönüştürülüp sunulur. Controller'lar, Model ile View arasında "yapıştırıcı" mantık görevi görür ve tipik olarak farklı URL'leri ele alan method'lara sahiptir. Önceki bölümde açıklandığı gibi, bir URL isteği yönlendirici tarafından bir controller'a iletildiğinde, controller bir eylemi gerçekleştirmesi için Model'e komutlar devreder, ardından View'ı herhangi bir değişiklikten haberdar eder. Bazı durumlarda ne modellerin herhangi bir mantıksal veya veri işlemesi yapmasına ne de herhangi bir view'ın render edilmesine gerek yoktur. Örneğin bir HTTP 302 yönlendirmesi durumunda, ne bir view render edilmesi gerekir ne de Model tarafından bir işlem yapılması gerekir; ancak Controller'ın işi yine de esastır.

## Beego'da RESTful tasarım

Önceki bölümde, route handler'ların RESTful struct'larla nasıl kaydedildiği açıklanmıştı. Şimdi, iki parçadan oluşacak bir mantık controller'ı için temel sınıfı tasarlamamız gerekiyor: bir struct ve bir interface tipi.

	type Controller struct {
		Ct        *Context
		Tpl       *template.Template
		Data      map[interface{}]interface{}
		ChildName string
		TplNames  string
		Layout    []string
		TplExt    string
	}

	type ControllerInterface interface {
		Init(ct *Context, cn string) //Context'i ve alt sınıf adını ilklendirir
		Prepare()                    //çalıştırma başlamadan önce yapılan bazı işlemler
		Get()                        //method = GET işlemesi
		Post()                       //method = POST işlemesi
		Delete()                     //method = DELETE işlemesi
		Put()                        //method = PUT işlemesi
		Head()                       //method = HEAD işlemesi
		Patch()                      //method = PATCH işlemesi
		Options()                    //method = OPTIONS işlemesi
		Finish()                     //işlem tamamlandıktan sonra çalıştırılır
		Render() error               //sayfayı render etmek için ilgili method'dan sonra çalıştırılan method
	}

Ardından, bu bölümün başında açıklanan route işleme fonksiyonunu ekleriz. Bir route, `ControllerInterface` tipi olarak tanımlandığında, bu interface'i uygulayabildiğimiz sürece, temel sınıf controller'ımızın aşağıdaki method'larına erişebiliriz.

    func (c *Controller) Init(ct *Context, cn string) {
		c.Data = make(map[interface{}]interface{})
		c.Layout = make([]string, 0)
		c.TplNames = ""
		c.ChildName = cn
		c.Ct = ct
		c.TplExt = "tpl"
	}
	
	func (c *Controller) Prepare() {
	
	}
	
	func (c *Controller) Finish() {
	
	}
	
	func (c *Controller) Get() {
		http.Error(c.Ct.ResponseWriter, "Method Not Allowed", 405)
	}
	
	func (c *Controller) Post() {
		http.Error(c.Ct.ResponseWriter, "Method Not Allowed", 405)
	}
	
	func (c *Controller) Delete() {
		http.Error(c.Ct.ResponseWriter, "Method Not Allowed", 405)
	}
	
	func (c *Controller) Put() {
		http.Error(c.Ct.ResponseWriter, "Method Not Allowed", 405)
	}
	
	func (c *Controller) Head() {
		http.Error(c.Ct.ResponseWriter, "Method Not Allowed", 405)
	}
	
	func (c *Controller) Patch() {
		http.Error(c.Ct.ResponseWriter, "Method Not Allowed", 405)
	}
	
	func (c *Controller) Options() {
		http.Error(c.Ct.ResponseWriter, "Method Not Allowed", 405)
	}
	
	func (c *Controller) Render() error {
		if len(c.Layout) > 0 {
			var filenames []string
			for _, file := range c.Layout {
				filenames = append(filenames, path.Join(ViewsPath, file))
			}
			t, err := template.ParseFiles(filenames...)
			if err != nil {
				Trace("template ParseFiles err:", err)
			}
			err = t.ExecuteTemplate(c.Ct.ResponseWriter, c.TplNames, c.Data)
			if err != nil {
				Trace("template Execute err:", err)
			}
		} else {
			if c.TplNames == "" {
				c.TplNames = c.ChildName + "/" + c.Ct.Request.Method + "." + c.TplExt
			}
			t, err := template.ParseFiles(path.Join(ViewsPath, c.TplNames))
			if err != nil {
				Trace("template ParseFiles err:", err)
			}
			err = t.Execute(c.Ct.ResponseWriter, c.Data)
			if err != nil {
				Trace("template Execute err:", err)
			}
		}
		return nil
	}
	
	func (c *Controller) Redirect(url string, code int) {
		c.Ct.Redirect(code, url)
	}	

Yukarıda, temel controller sınıfı interface'te tanımlanan fonksiyonları zaten uygulamış durumda. Yönlendirme kurallarımız sayesinde istek, uygun controller'a yönlendirilir ve bu controller sırasıyla şu method'ları çalıştırır:

    Init() ilklendirme rutini
    Prepare() ön ilklendirme rutini; her kalıtım alan alt sınıf bu fonksiyonu uygulayabilir
    method() istek method'una bağlı olarak farklı fonksiyonlar gerçekleştirir: GET, POST, PUT, HEAD vb. Alt sınıflar bu fonksiyonları uygulamalıdır; uygulanmazsa varsayılan olarak 403 döner
    Render() opsiyonel bir method'dur. Çalıştırılıp çalıştırılmayacağı global "AutoRender" değişkenine göre belirlenir
    Finish() eylem tamamlandıktan sonra çalıştırılır. Her kalıtım alan alt sınıf bu fonksiyonu uygulayabilir

## Uygulama rehberi

Yukarıda, Beego'nun temel controller sınıfının uygulamasını tartışmayı tamamladık. Şimdi bu bilgiyi kullanarak istek işlememizi tasarlayabilir, temel sınıftan kalıtım alıp gerekli method'ları kendi controller'ımızda uygulayabiliriz.

	package controllers
	
	import (
		"github.com/astaxie/beego"
	)
	
	type MainController struct {
		beego.Controller
	}
	
	func (this *MainController) Get() {
		this.Data["Username"] = "astaxie"
		this.Data["Email"] = "astaxie@gmail.com"
		this.TplNames = "index.tpl"
	}

Yukarıdaki kodda, yalnızca `Get()` method'unu uygulayan `MainController` adlı bir `Controller` alt sınıfı oluşturduk. Bir kullanıcı kaynağa diğer HTTP method'larından biriyle (POST, HEAD vb.) erişmeye çalışırsa, 403 Forbidden döndürülür. Ancak bir kullanıcı kaynağa bir GET isteği gönderirse ve `AutoRender` değişkenini `true` olarak ayarladıysak, kaynağın controller'ı otomatik olarak kendi `Render()` fonksiyonunu çağırır, ilgili şablonu render eder ve aşağıdaki gibi yanıt verir:

	<!DOCTYPE html>
	<html>
	  <head>
	    <title>beego welcome template</title>
	  </head>
	  <body>
	    <h1>Hello, world!{{.Username}},{{.Email}}</h1>
	  </body>
	</html>
